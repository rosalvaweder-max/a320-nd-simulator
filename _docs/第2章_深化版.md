## 第二章 A320导航显示器系统与导航理论分析

本章对A320导航显示器（ND）的系统架构、工作原理及导航计算理论基础进行深入分析。首先从信号输入与数据处理的角度剖析ND系统的整体架构，然后详细论述五种显示模式的技术特征与显示逻辑，接着分析ND的符号系统与颜色编码标准，最后建立导航计算的理论模型，包括坐标变换、VOR/ILS偏差计算和弧形过渡几何模型，为后续的系统设计与实现提供完整的理论基础。

### 2.1 导航显示器系统功能与架构

#### 2.1.1 ND系统的信号处理架构

A320导航显示器（ND）是电子飞行仪表系统（EFIS）的核心输出终端，其显示内容由多个航空电子子系统通过ARINC 429数据总线汇聚而成。ND系统的信号处理架构可分为三个层次：

**数据采集层**：多个传感器子系统实时采集飞行数据并通过ARINC 429总线传输。飞行管理引导系统（FMGS）提供飞行计划航路点坐标、航段类型和预计到达时间；惯性参考系统（IRS）以100Hz的更新率输出飞机位置（经纬度）、姿态角（横滚、俯仰、偏航）和地速矢量；大气数据惯性基准系统（ADIRS）提供真空速（TAS）、气压高度和垂直速度；导航接收机（VOR/ILS/DME）解算无线电导航参数，包括VOR径向方位、DME斜距和ILS航向道/下滑道偏差。

**数据处理层**：ND的显示管理计算机（DMC）对多源数据进行融合处理。坐标转换模块将地理坐标系（WGS-84经纬度）投影到平面显示坐标系；导航计算模块执行VOR径向偏差解算、ILS偏差归一化和飞行计划航段插值；符号生成模块根据当前显示模式选择可见元素集合，计算每个符号的屏幕位置和旋转角度。

**显示渲染层**：DMC将处理后的显示指令通过ARINC 453高速总线发送至显示单元，驱动CRT或LCD屏幕进行像素级渲染。本模拟器在Web环境中使用Canvas 2D API模拟这一渲染过程。

#### 2.1.2 五种显示模式的技术特征

A320 ND的五种显示模式覆盖了从航路巡航到精密进近的全飞行阶段，每种模式在坐标系统、视口变换和信息密度方面具有不同的技术特征：

**（1）ROSE NAV模式**：采用以飞机为中心的极坐标系，航向朝上的方位角显示方式。该模式的核心技术在于地图旋转——所有地理元素需绕飞机位置旋转（-heading）角度，使显示方向与飞机航向对齐。ROSE NAV模式的信息密度最高，同时显示飞行计划航路、导航台、气象雷达回波、TCAS交通目标和地形数据，对渲染性能要求最高。

**（2）ROSE ILS模式**：在ROSE NAV显示基础上叠加精密进近引导信息。该模式的关键技术在于偏差指示的归一化处理——航向道（LOC）偏差信号需从接收机原始电压值转换为标准化的偏转量，满偏量程对应±0.5°（2点偏差），每个刻度点代表0.8°的角偏差。下滑道（GS）偏差的满偏量程为±0.7°，每个刻度点约0.4°。偏差指示的平滑滤波算法直接影响显示稳定性。

**（3）ROSE VOR模式**：在ROSE NAV显示基础上叠加VOR导航引导信息。该模式的核心算法包括：VOR径向方位解算（基于飞机与VOR台的相对位置计算方位角）、航道偏离计算（选定径向线与飞机实际方位角的差值）、TO/FROM逻辑判断（基于飞机相对于选定径向线的位置象限）。VOR偏差的显示量程为±2点，每个刻度点代表5°的角偏差。

**（4）ARC模式**：采用扇形视口裁剪技术，仅显示飞机前方约100°的扇形空域。该模式的关键技术在于视口变换——将圆形罗盘坐标系映射到扇形显示区域，涉及极坐标到屏幕坐标的非线性变换。ARC模式的距离环使用同心圆弧代替完整圆环，弧长与扇形角度成正比。

**（5）PLAN模式**：采用北向上固定方位、目标航路点居中的显示方式。该模式不进行航向旋转，所有元素以地理北方向为基准。核心技术在于地图中心的动态切换——地图中心从飞机位置切换到目标航路点，飞机符号作为移动对象在地图上绘制。PLAN模式的距离环通常只显示一个虚线圆环，表示半量程范围。

### 2.2 导航显示器的显示参数与符号系统

#### 2.2.1 通用显示元素的技术分析

ND的通用显示元素在所有模式下均显示，其绘制涉及多种图形学技术：

**飞机符号**：采用黄色（Yellow）绘制，由机身线（长水平线）、机翼线（短水平线）和航向指示箭头组成。飞机符号的绘制需考虑Canvas坐标系的y轴反转特性——在ND显示坐标系中y轴向上，而Canvas的y轴向下，因此所有垂直方向需取反。飞机符号的旋转通过ctx.rotate()实现，旋转角度为当前航向的弧度值。

**罗盘玫瑰**：由同心圆环、角度刻度标记和方位标签组成。刻度标记的绘制采用极坐标到直角坐标的转换：对于角度θ，刻度线起点坐标为(cx + r₁·sinθ, cy - r₁·cosθ)，终点坐标为(cx + r₂·sinθ, cy - r₂·cosθ)，其中r₁和r₂分别为刻度线的内外半径。方位标签（N, 3, 6, 9等）的绘制需考虑文字对齐方式，使用ctx.textAlign和ctx.textBaseline进行精确控制。

**航向/航迹指示**：航向指示使用黄色固定标线配合移动罗盘实现，航迹指示使用绿色菱形标记。航迹标记的绘制需从航迹数据库获取实际飞行路径，通过等距方位投影将航迹点映射到屏幕坐标。

**数据块显示**：地速（GS）和真空速（TAS）以绿色字符显示在屏幕左上角，风向风速以数字和绿色箭头显示在GS/TAS下方。数据块的字体渲染使用等宽字体（monospace）模拟真实ND的字符显示风格，字符间距和行高需精确控制以匹配真实显示比例。

#### 2.2.2 模式专用显示元素的技术分析

**ILS模式专用元素**：航道指针（洋红色剑形符号）的绘制涉及复杂多边形路径构建，使用ctx.beginPath()、ctx.moveTo()和ctx.lineTo()定义剑形轮廓。偏离杆的横向偏移量通过归一化偏差值乘以最大偏移像素数计算：offsetPx = (locDeviation / locFullScale) × maxDeviationPx。下滑道偏差指示使用垂直刻度尺，洋红色菱形指示器沿垂直方向移动，其位置由gsDeviation参数决定。

**VOR模式专用元素**：航道偏差指示器（CDI）由航道杆、偏离杆和TO/FROM标志组成。航道杆的旋转角度为(selectedCourse - heading)，偏离杆的偏移量为deviation × scaleFactor。TO/FROM标志的绘制需根据飞机相对于选定径向线的位置进行判断：若飞机位于径向线的来向半平面则为TO，反之为FROM。方位指针的绘制从罗盘内圈延伸到外圈，两端绘制空心三角形指示方向。

### 2.3 EFIS控制面板的交互逻辑

EFIS控制面板是飞行员与ND系统交互的核心界面，其交互逻辑涉及状态转换、数据绑定和事件处理三个层面。

**模式选择旋钮**：实现五种ND模式之间的循环切换，切换逻辑为ROSE NAV → ROSE ILS → ROSE VOR → ARC → PLAN → ROSE NAV。模式切换时，ND显示内容需同步更新，同时部分模式专用控件（如VOR调谐区）的可见性需随之变化。

**范围选择旋钮**：支持六档量程（10/20/40/80/160/320 NM）的循环切换。量程变化直接影响地图缩放比例（pxPerNM = canvas有效半径 / range），以及距离环的标注值和显示数量。量程切换时，所有地图元素需重新计算屏幕坐标。

**VOR调谐控制**：支持自动/手动两种调谐模式。自动模式下，系统根据飞机当前位置自动选择最近的VOR台；手动模式下，用户通过频率旋钮（范围108.00-117.95 MHz，步进0.05 MHz）选择指定VOR台。CRS航道旋钮（范围0-360°，步进1°）用于设置VOR航道，支持循环绕回。

### 2.4 导航计算理论基础

导航计算是本模拟器实现ND显示功能的核心算法支撑，涉及坐标投影、无线电导航解算和飞行轨迹规划三个层面的数学建模。坐标投影解决地理坐标到屏幕坐标的映射问题，是地图元素准确定位的基础；VOR与ILS偏差计算从无线电导航原理出发，推导航道偏离和TO/FROM判断的具体算法，为导航引导功能提供数学依据；弧形过渡几何模型则从飞行轨迹规划的角度，给出转弯半径和弧形插值的计算方法，实现航段间的平滑过渡。以下各小节分别对这些计算模型进行详细论述。

#### 2.4.1 坐标系统、屏幕变换与飞机位置模拟

本系统采用简化的平面坐标模型，所有位置数据均通过运动学仿真引擎实时计算得到，而非来自真实的GPS信号或惯性导航系统。以下从坐标系统、屏幕变换和飞机位置模拟三个方面进行论述。

**（1）世界坐标系（NM平面坐标）**

所有航路点、导航台和飞机位置均使用以海里（NM）为单位的笛卡尔平面坐标表示，x轴指向东、y轴指向北。航路点数据直接以(x, y)形式存储，例如航路点LFPG（巴黎戴高乐机场）的坐标为(-120, 80) NM。

该坐标系的**原点(0, 0)为地图数据文件定义的一个虚拟参考中心**，所有航路点的坐标均相对于该中心定义，坐标范围约为x∈[-300, 100]、y∈[0, 200] NM。例如，LFPG位于中心以西120NM、以北80NM处，EGLL（伦敦希思罗机场）位于中心以西150NM、以北50NM处。这种平面坐标模型适用于区域范围的导航模拟，避免了球面坐标计算的复杂性。详见 [`data/default-route-map.json:8`](data/default-route-map.json:8) 中 `"coordinateSystem": "NM"`。

每个航路点同时存储了真实的经纬度坐标（lat/lon），用于与外部模拟器对接时的坐标转换。例如LFPG的真实位置为北纬49.0097°、东经2.5479°（巴黎戴高乐机场），其对应的平面坐标(-120, 80) NM是基于参考点（同样为巴黎戴高乐机场坐标）通过等距方位投影计算得到的近似值。详见 [`constants.js:137-196`](constants.js:137)。

**（2）屏幕坐标系与变换**

以Canvas左上角为原点，x轴向右，y轴向下。从世界坐标到屏幕坐标的转换公式为：

```
sx = (worldX - mapCenterX) × pxPerNM
sy = -(worldY - mapCenterY) × pxPerNM
```

其中(mapCenterX, mapCenterY)为地图中心的世界坐标（通常为飞机位置），pxPerNM为每海里对应的像素数。y坐标取反是因为Canvas坐标系y轴向下而ND坐标系y轴向上。详见 [`NDDisplay.js:240-241`](components/NDDisplay.js:240)。

pxPerNM的计算方式为：在ROSE模式下，pxPerNM = (canvas高度 × 0.45) / 当前量程。例如canvas高度为600px、量程为10NM时，pxPerNM = 270/10 = 27px/NM。量程切换时pxPerNM随之变化，所有地图元素需重新计算屏幕坐标。详见 [`NDDisplay.js:166`](components/NDDisplay.js:166)。

**（3）飞机位置模拟——运动学模型**

飞机位置通过运动学仿真引擎基于飞行计划中的航路点序列实时计算，模拟飞机沿预定航路的运动过程，为ND显示提供动态的位置数据源。计算过程涉及三种状态：

**初始位置设定**：当激活一条飞行计划航路时，系统从航路中读取第一个航路点的坐标作为飞机的初始位置，同时根据第一个航段的方向向量计算初始航向。初始航向的计算公式为：

```
initDx = nextWpt.x - startWpt.x
initDy = nextWpt.y - startWpt.y
initHeading = atan2(initDx, initDy) × 180 / π
```

其中 `atan2(initDx, initDy)` 返回的是**航空航向角**（以正北为0°，顺时针方向增大）。由于atan2的返回值范围是[-180°, 180°]，而航空航向的约定范围是[0°, 360°]，因此需要将负值结果加上360°，使其落入0-360°的约定范围内。例如，从LFPG(-120, 80)飞往EGLL(-150, 50)时，方向向量为(-30, -30)，atan2(-30, -30) = -135°，加上360°后得到初始航向225°（西南方向）。详见 [`App.js:137-161`](App.js:137)。

**直线段运动**：在直线飞行阶段，飞机沿当前航段方向匀速运动。每帧的位置更新公式为：

```
moveDist = (gs / 3600) × speedFactor × dt
newX = posX + (targetX - posX) / legLen × moveDist
newY = posY + (targetY - posY) / legLen × moveDist
```

其中(posX, posY)为飞机当前帧的起始位置（即上一帧计算得到的位置），(targetX, targetY)为当前目标航路点的世界坐标（即代码中的nextWpt.x和nextWpt.y，从飞行计划航路中读取的NM平面坐标值），legLen为飞机到目标航路点的直线距离。gs为地速（默认432节），speedFactor为速度倍率（支持×0.5至×4的倍率调节），dt为帧时间间隔（秒）。moveDist被限制不超过剩余航段距离，防止过冲。航向角通过atan2(targetX - posX, targetY - posY)实时计算，确保飞机始终指向目标航路点。详见 [`App.js:510-538`](App.js:510)。

**航路点过渡与第二段航向计算**：当飞机到达当前目标航路点（distToTarget < 0.3 NM）时，系统根据后续航路的情况分三种方式处理航向过渡：

**（a）需要转弯的过渡**：当入航航向与出航航向的夹角大于5°时，系统在接近航路点时已预先计算了转弯数据（turnData），其中出航航向outboundHeadingDeg通过atan2(outDx, outDy)预先计算并存储。飞机进入TURNING阶段，航向沿圆弧切线方向变化（详见2.4.4节弧形过渡几何模型）。当转弯完成（航向与出航航向一致）后，系统将targetIndex前进到下一个航路点，航向设置为预先计算的出航航向，恢复STRAIGHT阶段。详见 [`App.js:465-494`](App.js:465)、[`App.js:397-420`](App.js:397)。

**（b）无需转弯的过渡**：当航段夹角小于5°（近似直通）时，系统直接将targetIndex前进到下一个航路点，并基于新航段的方向向量重新计算航向：

```
newStartWpt = targetWpt
newEndWpt = route[nextIdx]
legDx = newEndWpt.x - newStartWpt.x
legDy = newEndWpt.y - newStartWpt.y
legHeading = atan2(legDx, legDy) × 180 / π
```

该公式与初始航向的计算公式完全相同，均使用atan2(dx, dy)的航空航向角约定。详见 [`App.js:495-508`](App.js:495)。

**（c）到达最后一个航路点（循环返回）**：当currentTargetIdx指向航路序列的最后一个元素时，系统将targetIndex重置为1（第二个航路点），飞机位置重置为第一个航路点，航向重新从第一个航段计算，实现循环飞行。详见 [`App.js:447-462`](App.js:447)。

以上三种过渡方式确保了飞行计划中多航段之间的连续导航，无论是否需要转弯，航向计算始终遵循统一的atan2(dx, dy)航空航向角标准。

**圆弧转弯运动**：当飞机到达航路点且需要改变航向时，进入转弯阶段。转弯采用标准速率转弯模型（3°/s），转弯半径由公式R = gs / (3600 × π/60)计算（约2.29 NM）。转弯过程中，飞机位置沿圆弧运动，每帧的角度步长为：

```
angularStep = moveDist / turnRadiusNM
currentAngle += isLeftTurn ? -angularStep : angularStep
newX = arcCenterX + sin(currentAngle) × turnRadiusNM
newY = arcCenterY + cos(currentAngle) × turnRadiusNM
```

其中arcCenter为转弯圆心坐标，位于入航方向垂直偏移转弯半径处（左转偏移-90°，右转偏移+90°）。转弯过程中的瞬时航向为圆弧切线方向，确保航向变化率恒定在3°/s。详见 [`App.js:370-439`](App.js:370)。

**位置数据的双重存储**：飞机位置同时存储在useRef（aircraftPosRef）和React state（aircraft）中。useRef提供同步读写能力，确保物理引擎每帧都能获取到最新的位置数据而不受React异步更新机制的影响；React state则驱动UI组件重新渲染，将位置信息传递给ND显示组件。这种双重存储策略在保证物理仿真精度的同时，维持了React声明式渲染的一致性。详见 [`App.js:115-116`](App.js:115)、[`App.js:542-549`](App.js:542)。

**（4）经纬度坐标支持（扩展接口）**

本系统在SimulatorIntegrationService中预留了经纬度到NM平面坐标的转换能力，使用Haversine公式计算大圆距离和方位角，再投影为笛卡尔坐标。该功能用于对接外部模拟器（如X-Plane）的GPS数据输入，但在本模拟器的独立运行模式下，所有位置数据直接使用NM平面坐标。详见 [`services/SimulatorIntegrationService.js:74-99`](services/SimulatorIntegrationService.js:74)。

#### 2.4.2 VOR导航原理与偏差计算

VOR（Very High Frequency Omnidirectional Range）系统通过比较30Hz参考信号和30Hz可变信号的相位差来确定飞机相对于VOR台的径向方位。本模拟器中VOR导航的核心计算包括：

**径向方位计算**：首先计算从飞机指向VOR台的方向角（bearingToVOR），再取其反向得到飞机径向方位（aircraftRadial，即从VOR台观察飞机的方向角，论文中记为radialBearing）：

```
dx = vorStation.x - aircraft.x
dy = vorStation.y - aircraft.y
bearingToVOR = (90 - atan2(dy, dx) × 180 / π + 360) % 360
aircraftRadial = (bearingToVOR + 180) % 360
```

其中bearingToVOR为从飞机指向VOR台的方位角，aircraftRadial为从VOR台指向飞机的径向方位角（即论文中的radialBearing）。`90 - atan2(dy, dx)`将数学坐标系（0°=东，逆时针为正）转换为航空坐标系（0°=北，顺时针为正）。详见 [`NDDisplay.js:863-872`](components/NDDisplay.js:863)。

**航道偏离计算**：选定航道（CRS）与飞机径向方位之间的角度差：

```
angularDev = aircraftRadial - vorCourse
```

偏差值需归一化到[-180°, 180°]范围：若angularDev > 180°，则angularDev -= 360°；若angularDev < -180°，则angularDev += 360°。归一化后的偏差值取反并限制在±20°满偏量程内，得到最终的偏离杆偏移量。详见 [`NDDisplay.js:904-909`](components/NDDisplay.js:904)。

**TO/FROM判断**：基于飞机航向与bearingToVOR的夹角进行判断：

```
headingDiff = (aircraft.heading - bearingToVOR + 360) % 360
isToMode = headingDiff < 90 || headingDiff > 270
```

若headingDiff < 90°或headingDiff > 270°，则为TO（飞向VOR台）；否则为FROM（飞离VOR台）。详见 [`NDDisplay.js:917-921`](components/NDDisplay.js:917)。

**偏离杆显示位置计算**：偏离杆的横向偏移量由偏差值乘以比例因子得到：

```
offsetPx = (angularDev_clamped / 20) × maxDeviationPx
```

其中满偏量程为±20°（对应2点偏差），maxDeviationPx为偏离杆的最大偏移像素数。

#### 2.4.3 ILS导航原理与偏差计算

ILS（Instrument Landing System）由航向台（LOC）和下滑台（GS）两部分组成，分别提供横向和垂直引导。

**航向道偏差计算**：飞机相对于跑道中心延长线的横向偏差：

```
locDeviation = (aircraftBearing - locCourse) / locFullScale
```

其中locFullScale对应±0.5°（2点偏差），每个刻度点代表0.8°。locDeviation的范围为[-1, 1]，对应满偏量程。

**下滑道偏差计算**：飞机相对于标准3°下滑角的垂直偏差：

```
gsDeviation = (aircraftElevationAngle - 3°) / gsFullScale
```

其中gsFullScale对应±0.7°，每个刻度点约0.4°。gsDeviation的范围为[-1, 1]。

**偏差指示的平滑滤波**：为防止偏差指示的剧烈抖动，采用一阶低通滤波器对原始偏差值进行平滑处理：

```
filteredDeviation = α × rawDeviation + (1 - α) × previousFilteredDeviation
```

其中α为滤波系数（通常取0.3-0.5），控制平滑程度。

#### 2.4.4 弧形过渡几何模型

在飞行计划中，飞机从一个航段过渡到另一个航段时，需要沿弧形路径转弯。弧形过渡的几何计算是飞行轨迹模拟的核心。

**转弯半径计算**：采用标准速率转弯（Standard Rate Turn，3°/s）模型：

```
R = V / (ω × π/180)
```

其中V为真空速（节），ω = 3°/s为标准转弯速率。例如，当V = 432节时，转弯半径R ≈ 432 / (3 × π/180) ≈ 2.29 NM。

**转弯方向判断**：根据入航航向和出航航向的夹角判断转弯方向。设入航航向为h₁，出航航向为h₂，转向角Δh = h₂ - h₁。若Δh > 0且Δh < 180°则为右转，若Δh < 0或Δh > 180°则为左转。

**弧形参数计算**：转弯弧的几何参数包括圆心坐标、起始角度和终止角度。圆心位于入航航向的垂直方向偏移转弯半径处。左转时圆心在入航方向的左侧（逆时针偏移90°），右转时在右侧（顺时针偏移90°）。

**弧形插值**：在圆弧上按固定角度步长采样，计算每个采样点的位置坐标和瞬时航向。采样点的位置通过极坐标转换得到：

```
x_i = cx + R · sin(θ_i)
y_i = cy + R · cos(θ_i)
```

其中(cx, cy)为圆心坐标，θ_i为第i个采样点的角度。这里使用sin(θ)计算x、cos(θ)计算y，是因为θ的定义遵循航空角度约定（0°指向正北，顺时针增大），与atan2(dx, dy)的返回值一致。

**弧线上的瞬时航向计算**：飞机在圆弧上运动时，航向为圆弧的切线方向，与径向方向垂直。具体计算公式为：

```
tangentAngle = θ + (isLeftTurn ? -90° : +90°)
```

其中θ为飞机当前位置在圆弧上的角度（从圆心到飞机的向量角度）。左转时，飞机沿逆时针方向绕圆心运动，航向比径向角小90°（航向递减）；右转时，飞机沿顺时针方向绕圆心运动，航向比径向角大90°（航向递增）。计算得到的tangentAngle需加360°归一化到0-360°范围。详见 [`App.js:431-436`](App.js:431)。

例如，飞机在圆弧上某点的径向角θ=45°（东北方向），若为左转，则瞬时航向 = 45° - 90° = -45° → 315°（西北方向），表示飞机正朝西北方向飞行；若为右转，则瞬时航向 = 45° + 90° = 135°（东南方向）。

综上所述，2.4节从坐标系统与屏幕变换、VOR/ILS导航解算到弧形过渡几何建模，建立了完整的导航计算理论体系。坐标系统部分明确了NM平面坐标模型和屏幕坐标变换的数学关系，并详细论述了飞机位置的运动学仿真方法；VOR与ILS偏差计算部分从无线电导航原理出发，推导了航道偏离、TO/FROM判断和偏差归一化的具体算法，为导航引导功能的实现提供了数学依据；弧形过渡几何模型则从飞行轨迹规划的角度，给出了转弯半径、圆心定位和弧形插值的计算方法，为飞行计划中航段间平滑过渡的实现奠定了几何基础。上述理论模型共同构成了本模拟器导航计算引擎的核心算法框架。

本章对A320导航显示器系统进行了深入的技术分析。从ND系统的信号处理架构出发，分析了数据采集层、数据处理层和显示渲染层的功能划分与数据流。详细论述了五种显示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN）的技术特征，包括坐标系统、视口变换和信息密度等方面的差异。对通用显示元素和模式专用显示元素的绘制技术进行了分析，涵盖极坐标转换、多边形路径构建、偏差归一化等关键技术。建立了完整的导航计算理论模型，包括等距方位投影的数学公式、VOR径向偏差和TO/FROM判断算法、ILS航向道/下滑道偏差计算方法，以及基于标准速率转弯的弧形过渡几何模型。本章的理论分析为后续的系统设计与实现提供了完整的数学基础和算法依据。
