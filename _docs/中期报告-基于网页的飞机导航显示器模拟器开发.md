## 一、进展情况（已取得的阶段性成果）及是否按照进度要求执行

### 1.1 项目概述

本课题旨在开发一款基于Web技术的A320飞机导航显示器（ND）模拟器，利用现代浏览器技术（HTML5 Canvas、React框架）实现高度真实的导航显示系统。项目采用模块化架构设计，支持多种显示模式、飞行计划管理、导航辅助设备显示、交通监控、天气雷达和地形感知等核心功能。

### 1.2 已完成的工作内容

截至中期报告提交时，项目已按照原定进度计划顺利完成了以下阶段性成果：

#### （1）系统架构设计与搭建

- **前端框架搭建**：基于React 19 + Vite 5构建了现代化前端应用，采用组件化开发模式，实现了高效的UI渲染和状态管理。
- **模块化架构设计**：采用三层架构设计——显示层（NDDisplay组件）、控制层（EFISPanel组件）、服务层（TCAS、天气、地形等服务），各层职责清晰、耦合度低。
- **Canvas 2D渲染引擎**：基于HTML5 Canvas API实现了高性能的2D图形渲染引擎，支持60FPS的流畅动画渲染。

#### （2）五种ND显示模式实现

- **ROSE NAV模式**：实现了完整的360°罗盘玫瑰导航显示，飞机位于屏幕中心，航向朝上，显示飞行计划航路、航路点、导航辅助设备等信息。
- **ROSE ILS模式**：实现了仪表着陆系统显示，包括航向道（LOC）偏差指示和下滑道（GS）偏差指示，支持进近过程中的精密导航引导。
- **ROSE VOR模式**：实现了VOR导航显示，包括航道偏离指示器（CDI）、十字杆（Course Dagger）、TO/FROM标志、VOR径向偏差计算等核心功能。
- **ARC模式**：实现了弧形显示模式，飞机位于屏幕底部，显示前方140°扇形空域，航向朝上，适用于航路监控和进近阶段。
- **PLAN模式**：实现了计划模式显示，北向上固定方位，以目标航路点为中心显示完整的飞行计划航路，适用于航路规划和审查。

#### （3）飞行计划管理系统

- **航路点管理**：支持航路点的增删改查操作，包括名称、类型（VOR/NDB/FIX/AIRPORT）、坐标等属性编辑。
- **航路管理**：支持多条航路的创建、删除、激活、设为备用等操作。
- **航路点连接管理**：支持航路点之间的连接/断开操作，可创建带中断的航路。
- **航路点排序**：支持拖拽排序功能，方便调整航路点顺序。
- **地图数据加载**：支持从URL和本地文件加载JSON格式的地图数据，包括航路点、导航台、航路和地形数据。

#### （4）导航辅助设备显示系统

- **VOR显示**：实现了完整的VOR导航台显示，包括VOR符号、频率、识别码、距离信息；支持自动/手动调谐模式；实现了VOR径向偏差计算和航道偏离指示。
- **NDB显示**：实现了NDB导航台符号显示和基本信息展示。
- **机场显示**：实现了机场符号绘制和ICAO代码显示。

#### （5）高级功能系统

- **TCAS交通防撞系统**：实现了TCAS I/II级别的交通监控功能，包括相对高度指示、威胁等级评估（OTHER/TRAFFIC/PROXIMATE/TA/RA）、垂直速度指示、Resolution Advisory（RA）逻辑。
- **天气雷达系统**：实现了气象雷达回波模拟，支持多种天气模式（晴空、孤立单体、散落单体、破碎层云、阴天覆盖），包括湍流区域检测和显示。
- **地形感知与警告系统（EGPWS）**：实现了增强型近地警告系统的地形显示功能，包括地形等高线绘制、基于海拔高度的颜色编码（绿色→黄色→红色）、地形净空计算。

#### （6）性能优化系统

- **三级性能优化策略**：
  - **显示列表（Display List）**：缓存渲染指令，减少重复计算
  - **脏矩形管理（Dirty Rectangle Manager）**：仅重绘变化区域
  - **空间索引（Spatial Index）**：基于网格的空间查询加速
- **对象池（Object Pool）**：减少内存分配和垃圾回收开销
- **帧率控制器（Frame Rate Controller）**：自适应帧率调节，确保在复杂场景下保持流畅体验
- **渲染质量自适应**：根据显示范围自动调整渲染质量（HIGH/MEDIUM/LOW）

#### （7）显示效果系统

- **CRT显示效果**：实现了荧光辉光、扫描线、汇聚误差、泛光效果、屏幕曲率、闪烁噪声等复古CRT显示器效果。
- **LCD显示效果**：实现了像素网格、背光渗漏、色温调节、视角效果、响应时间模拟等现代LCD显示器效果。
- **环境效果**：实现了日光冲刷、夜间调暗、雨滴效果、屏幕污渍、老化效果等环境模拟。
- **OLED/单色/夜视模式**：支持多种显示类型切换。

#### （8）EFIS控制面板

- **模式选择**：支持NAV/ARC/PLAN/VOR/ILS五种模式的切换。
- **范围选择**：支持10/20/40/80/160/320 NM六档范围选择。
- **气压基准设置**：支持QNH/QFE切换和气压值调节。
- **VOR调谐控制**：支持自动/手动调谐模式，频率微调功能。
- **数据显示控制**：支持航路点、VOR、NDB、机场等数据的显示切换。

#### （9）模拟器集成服务

- **数据适配层**：实现了飞行数据（FlightData）类，支持经纬度坐标与笛卡尔坐标的转换。

## 二、存在的问题及解决思路

### 2.1 技术问题

#### 问题1：飞机在转弯时无法沿航路运动

**问题描述**：在NAV和VOR模式下，当飞行计划中的连续航段之间存在航向变化时，飞机需要从当前航段过渡到下一航段。在初始实现中，飞机在转弯过程中无法沿预定航路运动，具体表现为：飞机到达航路点后直接跳转到下一航段，转弯过程中偏离航路，无法平滑地沿弧形过渡路径飞行。

**原因分析**：
- 初始实现中，飞机的运动逻辑仅支持沿直线航段飞行，缺乏弧形过渡（ARC）的几何计算模型。
- 当飞机通过航路点时，目标航路点（nextWaypointId）直接切换到下一航段终点，飞机航向瞬间跳变，导致运动轨迹出现折线而非平滑曲线。
- 缺乏转弯半径、转弯方向、切入/切出点等关键参数的动态计算逻辑。

**解决思路**：
- **引入弧形过渡几何模型**：在连续航段之间插入弧形过渡路径，根据入航航向、出航航向和转弯半径计算弧形参数（圆心坐标、起始角度、终止角度、转弯方向）。
- **实现ARC飞行阶段**：在动画循环中增加ARC飞行阶段处理逻辑，当飞机接近航路点时自动从STRAIGHT（直线）阶段切换为ARC（弧形）阶段，完成转弯后切回STRAIGHT阶段。
- **动态航向计算**：在弧形过渡过程中，根据飞机在圆弧上的当前位置实时计算瞬时航向（圆弧切线方向），确保飞机航向连续平滑变化。
- **航路点切换时机优化**：在飞机完成弧形过渡、航向稳定对准下一航段后，再切换目标航路点，避免过早切换导致的航向跳变。

#### 问题2：VOR模式转弯时显示不一致

**问题描述**：在VOR模式下，当飞机进行转弯（ARC过渡）时，十字杆（Course Dagger）的指向和偏离杆（Deviation Bar）的移动与飞机的实际运动不一致。具体表现为：十字杆在航路点切换时发生跳变，偏离杆在转弯过程中出现不规则的左右摆动。

**原因分析**：
- 十字杆的航道角（CRS）原设置为固定值（当前航段的入航方向），当飞机通过航路点后，航道角突然跳变为下一航段的出航方向，导致十字杆瞬间旋转。
- 偏离量的计算基于飞机到航段的交叉航迹误差（XTE），但在弧形转弯过程中，飞机沿曲线飞行，交叉航迹误差会急剧增大并快速变化，导致偏离杆异常摆动。
- 偏离量的符号约定与显示系统的坐标系不匹配。

**解决思路**：
- **平滑航道过渡**：引入投影系数（projT），根据飞机在入航航段上的投影位置，在入航航道角和出航航道角之间进行线性插值，实现航道角的平滑过渡（过渡窗口为0.8~1.2倍航段长度）。
- **基于VOR径向的偏差计算**：将偏离量的计算方式从交叉航迹误差改为基于VOR径向偏差，即计算飞机相对于VOR台的径向线与选定航道之间的角度差，更符合真实VOR导航原理。
- **修正符号约定**：根据显示系统的坐标系约定，对偏离量取反，确保偏离杆的偏转方向与VOR标准一致（飞机偏右→偏离杆偏左→"向左飞"指示）。

#### 问题3：ARC模式航向计算精度

**问题描述**：在ARC模式下，飞机沿弧形航路飞行时，航向的计算在某些边界条件下出现不连续或跳变。

**原因分析**：
- 弧形过渡的几何计算涉及起点切线方向、终点切线方向和弧形半径等多个参数，在特定几何构型下（如大角度转弯、短航段），数值计算可能出现不稳定。
- 航向的跨360°边界处理不够完善。

**解决思路**：
- 优化弧形几何算法，增加数值稳定性检查。
- 完善角度归一化处理，确保航向值始终在0°~360°范围内连续变化。
- 增加弧形过渡的中间航路点采样，提高航向变化的平滑度。

#### 问题4：性能优化在复杂场景下的瓶颈

**问题描述**：当同时显示大量航路点（50+）、TCAS目标（20+）、天气回波和地形数据时，帧率下降到30FPS以下。

**原因分析**：
- 脏矩形管理在大量动态对象同时移动时，合并效率下降，导致全屏重绘。
- 空间索引的网格分辨率固定，无法自适应调整。
- 天气和地形数据的渲染计算量较大。

**解决思路**：
- **动态网格调整**：根据当前场景复杂度动态调整空间索引的网格大小。
- **LOD（细节层次）技术**：根据缩放级别和对象距离，动态调整渲染精度，远处对象使用简化符号。
- **Web Worker并行计算**：将天气和地形的数据计算迁移到Web Worker线程，避免阻塞主线程渲染。
- **离屏Canvas缓存**：对静态背景（如罗盘玫瑰、范围环）使用离屏Canvas缓存，减少重复绘制。

### 2.2 功能完整性问题

#### 问题5：与真实A320 ND的功能差距

**问题描述**：当前实现与真实A320 ND相比，仍存在以下功能差距：

| 缺失功能 | 影响程度 | 说明 |
|---------|---------|------|
| ADF指示器 | 中 | 缺乏ADF指针和相对方位显示 |
| 航路点预测（TTG/DTW/ETA） | 高 | 缺乏时间/距离/预计到达时间计算 |
| 垂直导航（VNAV） | 中 | 缺乏下降顶点（TOD）预测和垂直剖面显示 |
| 风数据集成 | 中 | 缺乏风三角计算和风数据显示 |
| 燃油管理 | 低 | 缺乏燃油预测和备降场计算 |
| 自动驾驶状态显示 | 中 | 缺乏AP/FD模式指示 |
| 系统故障模式 | 低 | 缺乏详细故障指示 |

**解决思路**：
- **分阶段实施**：按照优先级逐步实现缺失功能。
  - **第一阶段（高优先级）**：实现TTG/DTW/ETA计算引擎和风数据集成，这两项功能对导航训练的真实性影响最大。
  - **第二阶段（中优先级）**：实现ADF指示器、VNAV基本功能和自动驾驶状态显示。
  - **第三阶段（低优先级）**：实现燃油管理和系统故障模式。
- **模块化开发**：每个功能作为独立模块开发，通过服务层接口与现有系统集成，降低耦合度。
- **数据驱动**：建立统一的数据计算服务（NavigationCalculator），集中管理所有导航计算逻辑。

#### 问题6：地图数据格式和兼容性

**问题描述**：当前地图数据使用自定义JSON格式，与标准ARINC 424导航数据库格式不兼容，限制了数据来源。

**解决思路**：
- 开发数据格式转换器，支持从ARINC 424、Jeppesen等标准格式导入数据。
- 扩展地图数据服务（MapDataService），增加数据验证和标准化功能。
- 提供数据编辑工具，方便用户创建和修改地图数据。

### 2.3 用户体验问题

#### 问题7：控制面板交互体验

**问题描述**：EFIS控制面板的旋钮和按钮交互以鼠标点击为主，缺乏真实的旋转操作感和触觉反馈。

**解决思路**：
- 实现鼠标拖拽旋转旋钮的交互方式，模拟真实旋钮的操作感。
- 增加音频反馈（旋钮咔嗒声、按钮点击声），提升操作真实感。
- 优化按钮的视觉反馈（LED状态指示、背光效果）。
- 支持键盘快捷键操作，提高操作效率。

### 3.3 研究内容重点

下一阶段的研究内容将围绕以下三个重点方向展开：

#### （1）导航计算算法的精确性研究

- **大圆距离计算**：研究基于WGS-84椭球模型的大圆距离计算算法，确保长距离导航计算的精度。
- **VOR/ILS偏差计算**：深入研究VOR径向偏差和ILS航向道/下滑道偏差的物理模型和计算方法。
- **风三角计算**：研究真航向、风修正角、航迹角之间的三角关系，实现精确的风数据计算。

#### （2）系统性能优化技术研究

- **渲染管线优化**：研究Canvas 2D渲染管线的性能瓶颈，探索离屏渲染、分层渲染等优化技术。
- **数据并行处理**：研究Web Worker在导航数据计算中的应用，实现计算与渲染的并行处理。
- **内存管理优化**：研究对象池、懒加载、数据缓存等内存管理技术，减少内存碎片和GC压力。

#### （3）用户体验真实性提升研究

- **交互方式研究**：研究真实A320驾驶舱EFIS控制面板的交互逻辑和操作手感，在Web环境中实现高保真模拟。
- **视觉真实性研究**：研究真实A320 ND的显示特性（颜色、字体、符号、动画），在Canvas渲染中精确复现。
- **音频反馈研究**：研究驾驶舱环境中的音频反馈系统，实现旋钮、按钮、告警等声音的模拟。

### 3.4 预期成果

2. **系统稳定性**：修复所有已知技术问题，系统在主流浏览器（Chrome/Firefox/Edge）上稳定运行。

4. **用户体验**：EFIS控制面板交互真实感显著提升，显示效果更接近真实A320 ND。
