## 摘  要

航空电子显示系统是飞机驾驶舱的核心组成部分，导航显示器（Navigation Display, ND）为飞行员提供关键的态势感知信息。本论文设计并实现了一套基于Web技术的A320导航显示器模拟系统，采用React 19框架与HTML5 Canvas 2D渲染引擎，在浏览器环境中模拟了A320 ND的五种显示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN）。系统采用三层模块化架构，涵盖显示层、控制层与服务层，实现了飞行计划管理、VOR/ILS导航显示、TCAS交通防撞系统、天气雷达模拟、增强型近地警告系统（EGPWS）以及CRT/LCD显示效果模拟等功能。针对Canvas渲染性能瓶颈，设计并实现了包含显示列表缓存、脏矩形管理与空间索引的三级性能优化策略，确保在复杂场景下维持30 FPS以上的流畅帧率。实验结果表明，本系统在功能完整性、显示真实性与运行性能方面均达到了预期目标，可作为航空电子教学训练与飞行程序研究的有效工具。

## ABSTRACT

Avionics display systems are core components of modern aircraft cockpits, among which the Navigation Display (ND) provides pilots with critical situational awareness information. This thesis designs and implements a web-based A320 Navigation Display simulator system, utilizing the React 19 framework and HTML5 Canvas 2D rendering engine to faithfully simulate five display modes (ROSE NAV, ROSE ILS, ROSE VOR, ARC, PLAN) of the real A320 ND in a browser environment. The system adopts a three-layer modular architecture covering the presentation layer, control layer, and service layer, implementing core functionalities including flight plan management, VOR/ILS navigation display, TCAS traffic collision avoidance system, weather radar simulation, Enhanced Ground Proximity Warning System (EGPWS), and CRT/LCD display effect simulation. To address Canvas rendering performance bottlenecks, a three-level performance optimization strategy incorporating display list caching, dirty rectangle management, and spatial indexing has been designed and implemented, ensuring a smooth frame rate above 30 FPS under complex scenarios. Experimental results demonstrate that the system achieves the expected goals in terms of functional completeness, display authenticity, and operational performance, serving as an effective tool for avionics education, training, and flight procedure research.

**Keywords:** A320 Navigation Display; Web Simulator; Canvas 2D Rendering; Avionics Systems; Flight Simulation

## 第一章 绪论

### 1.1 研究背景与意义

航空电子系统（Avionics）是现代民用航空器的核心组成部分，它的发展水平直接影响飞行安全、运营效率和飞行员的工作负荷。随着航空技术的不断进步，传统的机电式飞行仪表已逐步被电子飞行仪表系统（Electronic Flight Instrument System, EFIS）所取代。在众多民航机型中，空中客车A320系列飞机作为全球最畅销的单通道客机之一，其玻璃驾驶舱（Glass Cockpit）设计理念代表了现代民航机驾驶舱的典型架构，因此被选为本系统的模拟对象。

选择A320作为模拟对象，主要有以下几个方面的考虑：

**（1）市场占有率与行业影响力。** A320系列飞机在全球范围内运营数量极大，截至2025年已交付超过11,000架，全球超过300家航空公司运营该机型。庞大的运营基数意味着对A320相关训练设备的需求持续存在，开发A320 ND模拟器具备广泛的应用前景。

**（2）玻璃驾驶舱的代表性。** A320是全球首款大规模采用电传操纵（Fly-by-Wire）技术与全玻璃驾驶舱的商用客机，其EFIS系统的设计理念深刻影响了后续所有机型（包括Boeing 777、B787、A350等）。掌握A320 ND的模拟技术，可以为其他机型的模拟开发提供重要的技术参考。

**（3）技术资料的可获取性。** 空中客车公司公开了大量A320相关技术资料，包括飞行机组操作手册（Flight Crew Operating Manual, FCOM）[1]、飞机维修手册（Aircraft Maintenance Manual, AMM）[2]以及航空电子系统描述文件，为精确模拟提供了可靠的技术依据。

**（4）ND系统的完整性与复杂性。** A320 ND支持五种显示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN），涵盖从航路巡航到精密进近的全飞行阶段显示需求。其显示逻辑涵盖VOR/ILS导航、TCAS交通监控、天气雷达、EGPWS地形感知等多个子系统，功能完整且具有适度的复杂性，既能体现航空电子系统的核心技术特征，又能在Web环境中实现可控的模拟范围。

**（5）教学与训练价值。** A320 ND系统涵盖了航空电子显示系统的核心概念，包括坐标变换、符号生成、导航计算、多层次渲染等技术要点，是航空电子工程、计算机科学、自动化等非飞行专业学生理解航空电子系统工作原理的理想教学案例。基于Web的模拟器无需专用硬件设备，为非飞行专业学生提供了低成本、高可访问性的实践学习平台，有助于缩短理论教学与工程实践之间的差距。

A320的导航显示器（Navigation Display, ND）是EFIS系统的关键组成部分，位于驾驶舱正前方仪表板中央位置，为飞行员提供全面的导航态势感知信息。ND能够以多种显示模式呈现飞行计划航路、导航辅助设备（VOR/NDB）、气象雷达回波、交通防撞系统（TCAS）信息以及地形感知数据，是飞行员进行航路监控、态势判断与决策制定的核心视觉界面。

然而，真实的A320 ND系统存在一些局限性：（1）造价昂贵，一台完整的ND训练设备成本高达数十万美元；（2）操作环境封闭，难以进行功能扩展与二次开发；（3）教学资源有限，非飞行专业学生难以接触到真实的航空电子显示设备。因此，开发一套基于Web技术的A320 ND模拟器具有重要的理论与实践意义：

**（1）降低教学门槛。** 基于Web的模拟器无需专用硬件设备，仅需标准浏览器即可运行，大幅降低了航空电子教学的硬件门槛，使非飞行专业学生也能够直观地理解航空电子显示系统的工作原理。

**（2）提高可访问性。** Web应用的跨平台特性使得学生可以在任何具备浏览器的设备上进行学习与实验，包括个人电脑、平板电脑等，突破了时间与空间的限制。

**（3）促进教学创新。** 开放的Web技术栈使得教师可以根据教学需要自定义实验场景、修改显示逻辑，为航空电子课程的理论教学与实验环节提供了极大的灵活性。

**（4）技术验证平台。** 本系统可作为航空电子新技术（如新型导航显示格式、增强型态势感知界面）的快速原型验证平台，为航空电子工程相关专业的学生提供工程实践环境。

### 1.2 国内外研究现状

#### 1.2.1 国外研究现状

在国际上，航空模拟器技术已发展得比较成熟。以CAE、L3Harris、FlightSafety International为代表的专业模拟器制造商提供了从全任务模拟器（Full Flight Simulator, FFS）到桌面训练设备（Desktop Training Device, DTD）的全系列产品。在开源与学术领域，X-Plane、Microsoft Flight Simulator等消费级飞行模拟平台提供了丰富的SDK与插件接口，支持第三方开发者进行航空电子系统的模拟开发。

在ND模拟器方面，部分开源项目如OpenFlightSim、YASim等提供了基本的导航显示功能，但通常存在以下不足：（1）显示精度较低，符号系统与真实A320 ND存在较大差距；（2）功能不完整，缺乏TCAS、天气雷达等高级功能；（3）性能优化不足，在复杂场景下帧率不稳定。

#### 1.2.2 国内研究现状

国内在航空模拟器领域的研究起步相对较晚，但近年来发展速度较快。北京航空航天大学、南京航空航天大学、中国民航大学等高校在飞行模拟器、航空电子系统模拟方面开展了大量研究工作。在Web-based航空模拟方面，部分研究尝试利用HTML5技术实现飞行仪表的模拟，但多集中于主飞行显示器（Primary Flight Display, PFD）的模拟，针对ND系统的完整模拟研究相对较少。

现有国内研究中，ND模拟器普遍存在以下问题：（1）显示模式单一，通常仅实现ROSE NAV模式；（2）缺乏完整的VOR/ILS导航逻辑模拟；（3）未实现TCAS、天气雷达等高级功能；（4）性能优化不足，无法满足流畅交互的需求。

#### 1.2.3 现有研究的不足

综合分析国内外研究现状，现有ND模拟器研究存在以下主要不足：

1. **功能完整性不足。** 多数模拟器仅实现了基本的导航显示功能，缺乏对TCAS、天气雷达、EGPWS等高级功能的支持。
2. **显示真实性有限。** 符号系统、颜色方案与真实A320 ND标准存在较大差距，影响训练效果。
3. **性能优化欠缺。** 缺乏系统性的性能优化策略，在复杂场景下难以维持流畅的交互体验。
4. **架构可扩展性差。** 模块化设计不足，新增功能需要大量修改既有代码。

### 1.3 论文主要工作

本论文旨在设计并实现一套基于Web技术的高保真A320 ND模拟器，主要工作包括：

1. **系统架构设计。** 采用三层模块化架构，将系统划分为显示层、控制层与服务层，各层次职责清晰、耦合度低，支持功能扩展与维护。

2. **五种ND显示模式实现。** 完整实现ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN五种显示模式，每种模式均遵循真实A320 ND的显示逻辑与符号标准。

3. **导航计算引擎。** 实现VOR径向偏差计算、ILS航向道/下滑道偏差计算、弧形过渡几何模型等核心导航算法。

## 第二章 相关技术与理论基础

### 2.1 A320导航显示器系统概述

#### 2.1.1 ND系统功能与架构

A320导航显示器（ND）是电子飞行仪表系统（EFIS）的重要组成部分，位于驾驶舱正前方仪表板中央位置。ND的主要功能是为飞行员提供全面的导航态势感知信息，包括飞行计划航路显示、导航辅助设备定位、气象雷达回波、交通防撞信息以及地形感知数据。

ND系统的输入来源包括：（1）飞行管理引导系统（Flight Management and Guidance System, FMGS），提供飞行计划数据与导航计算结果；（2）惯性参考系统（Inertial Reference System, IRS），提供飞机姿态与位置信息；（3）大气数据惯性基准系统（Air Data Inertial Reference System, ADIRS），提供空速、高度等大气数据；（4）导航接收机（VOR/ILS/DME接收机），提供无线电导航信息；（5）气象雷达接收机，提供天气回波数据；（6）TCAS计算机，提供交通监控信息。

#### 2.1.2 五种显示模式

A320 ND支持五种显示模式，每种模式适用于不同的飞行阶段与任务需求：

**（1）ROSE NAV模式：** 全罗盘玫瑰导航模式，飞机位于显示器中心，航向朝上。显示完整的360°罗盘玫瑰、飞行计划航路、航路点、导航辅助设备等信息。适用于航路巡航阶段的导航监控。

**（2）ROSE ILS模式：** 仪表着陆系统模式，在ROSE NAV显示的基础上叠加ILS航向道（LOC）与下滑道（GS）偏差指示。适用于精密进近阶段的引导。

**（3）ROSE VOR模式：** VOR导航模式，在ROSE NAV显示的基础上叠加VOR航道偏差指示器（CDI），包括航道杆、偏离杆、TO/FROM标志等。适用于VOR导航与非精密进近。

**（4）ARC模式：** 弧形显示模式，飞机位于显示器底部中心，显示前方约100°~140°扇形空域。航向朝上，显示飞行计划航路与导航信息。适用于航路监控与进近阶段。

**（5）PLAN模式：** 计划模式，北向上固定方位，以目标航路点为中心显示完整的飞行计划航路。不显示飞机实时位置，适用于航路规划与审查。

#### 2.1.3 颜色标准与符号系统

A320 ND采用标准化的颜色编码系统，以确保信息传递的一致性和可读性：

- **洋红色（Magenta）：** 表示主动飞行计划、选定数据、主动航段
- **青色（Cyan）：** 表示飞行计划航路、航路点、导航辅助设备
- **绿色（Green）：** 表示主动航段、航迹线
- **黄色（Yellow）：** 表示飞机符号、注意指示
- **琥珀色（Amber）：** 表示警告、建议
- **红色（Red）：** 表示警报、故障

### 2.2 Web前端技术栈

#### 2.2.1 React 19框架

React是由Meta（原Facebook）开发的用于构建用户界面的JavaScript库。React 19作为最新稳定版本，引入了多项重要特性：

- **并发模式（Concurrent Mode）：** 允许React中断长时间运行的渲染任务，优先处理高优先级更新，提升用户体验。
- **服务器组件（Server Components）：** 支持在服务器端渲染组件，减少客户端JavaScript体积。
- **改进的Suspense机制：** 提供更优雅的异步数据加载处理方式。

在本系统中，React 19被选为UI框架的主要原因包括：（1）组件化开发模式，便于模块化架构的实现；（2）虚拟DOM机制，减少实际DOM操作次数；（3）丰富的生态系统与社区支持。

#### 2.2.2 Vite 5构建工具

Vite是一个现代化的前端构建工具，利用原生ES模块（ESM）实现开发服务器的快速启动与热模块替换（HMR）。Vite 5在以下方面表现优异：

- **极速冷启动：** 基于ESM的开发服务器无需打包，启动速度远快于Webpack等传统工具。
- **高效的HMR：** 模块级别的热更新，修改代码后仅重新编译受影响的模块。
- **优化的生产构建：** 基于Rollup的生产构建，支持代码分割（Code Splitting）与树摇（Tree Shaking）。

#### 2.2.3 ES Modules模块化

本系统采用ES Modules（ESM）作为模块化方案，利用`import`与`export`语句实现模块的加载与导出。ESM具有以下优势：

- **静态分析：** 编译时即可确定模块的依赖关系，支持树摇优化。
- **异步加载：** 支持动态`import()`实现按需加载。
- **严格的模块作用域：** 每个模块拥有独立的作用域，避免全局变量污染。

### 2.3 Canvas 2D渲染技术

#### 2.3.1 Canvas API概述

HTML5 Canvas提供了一个基于像素的2D绘图表面，通过JavaScript API进行图形绘制。Canvas 2D渲染管线包括以下主要步骤：

1. **获取渲染上下文：** 通过`canvas.getContext('2d')`获取2D渲染上下文。
2. **设置绘图状态：** 设置线条样式（`strokeStyle`）、填充样式（`fillStyle`）、线宽（`lineWidth`）、变换矩阵（`transform`）等。
3. **定义路径：** 使用`beginPath()`、`moveTo()`、`lineTo()`、`arc()`等方法定义绘图路径。
4. **执行绘制：** 使用`stroke()`或`fill()`方法执行实际绘制。
5. **状态保存与恢复：** 使用`save()`与`restore()`方法管理绘图状态栈。

#### 2.3.2 Canvas性能优化策略

Canvas 2D渲染的性能瓶颈主要来自：（1）大量绘图调用导致的CPU开销；（2）像素操作（如`getImageData`/`putImageData`）的内存带宽消耗；（3）Canvas尺寸过大导致的GPU内存压力。

针对上述瓶颈，常见的优化策略包括：

- **离屏Canvas缓存：** 将静态内容（如罗盘玫瑰、范围环）渲染到离屏Canvas，主Canvas仅渲染动态内容。
- **分层渲染：** 将不同类型的内容（如背景、航路、动态元素）分配到不同的Canvas图层，减少重绘面积。
- **脏矩形更新：** 仅重绘发生变化的区域，而非整个Canvas。
- **请求动画帧（requestAnimationFrame）：** 使用浏览器提供的动画帧机制，避免不必要的渲染。

### 2.4 导航计算理论基础

#### 2.4.1 坐标系统与变换

本系统涉及多个坐标系统的转换：

**（1）地理坐标系（经纬度）：** 使用WGS-84椭球模型，以经度（λ）和纬度（φ）表示位置。

**（2）笛卡尔坐标系（Canvas坐标）：** 以像素为单位，x轴向右，y轴向下。

**（3）ND显示坐标系：** 以显示器中心为原点，x轴向右，y轴向上（与Canvas坐标系y轴方向相反）。

坐标转换流程如下：

```
地理坐标(λ, φ) → 平面投影(x, y) → 屏幕坐标(sx, sy)
```

其中，平面投影采用等距方位投影（Azimuthal Equidistant Projection），以飞机位置为投影中心。

#### 2.4.2 VOR导航原理

VOR（Very High Frequency Omnidirectional Range）是一种基于地面台的短程无线电导航系统。VOR台发射两个信号：（1）一个全向参考信号；（2）一个旋转方向性信号。机载接收机通过比较两个信号的相位差来确定相对于VOR台的径向方位。

VOR导航的核心计算包括：

**（1）径向方位计算：** 飞机相对于VOR台的方位角，计算公式为：

```
θ = atan2(Δx, Δy)
```

其中Δx和Δy为飞机相对于VOR台的笛卡尔坐标差。

**（2）航道偏离计算：** 飞机当前径向与选定航道之间的角度差：

```
deviation = selectedRadial - aircraftRadial
```

**（3）TO/FROM判断：** 根据飞机相对于选定航道的位置判断：

- TO：飞机位于选定航道的来向方向
- FROM：飞机位于选定航道的去向方向

#### 2.4.3 ILS导航原理

ILS（Instrument Landing System）是一种精密进近引导系统，由三个部分组成：

**（1）航向台（Localizer, LOC）：** 提供横向引导，发射方向性信号，在跑道中心延长线上形成航向道。

**（2）下滑台（Glideslope, GS）：** 提供垂直引导，发射方向性信号，形成标准的3°下滑角。

**（3）指点标台（Marker Beacons）：** 提供距离跑道入口的距离参考。

ILS偏差计算：

```
locDeviation = (aircraftBearing - locCourse) / locFullScale
gsDeviation = (aircraftElevationAngle - gsAngle) / gsFullScale
```

其中，locFullScale通常对应±0.5°（2点偏差），gsFullScale通常对应±0.7°。

#### 2.4.4 弧形过渡几何模型

在飞行计划中，当飞机从一个航段过渡到另一个航段时，需要沿弧形路径转弯。弧形过渡的几何计算包括：

**（1）转弯半径计算：**

```
R = V² / (g × tan(φ))
```

其中V为真空速，g为重力加速度，φ为坡度角。

**（2）弧形参数计算：**

- 圆心坐标：根据入航航向、出航航向和转弯半径计算
- 起始角度：入航航向对应的圆弧起始点
- 终止角度：出航航向对应的圆弧终止点
- 转弯方向：左转或右转

**（3）弧形插值：** 在圆弧上按角度步长采样，计算每个采样点的位置与瞬时航向（圆弧切线方向）。

#### 3.2.2 数据流设计

系统的数据流遵循单向数据流（Unidirectional Data Flow）原则：

```
用户操作 → Event Handler → State Update → Re-render
```

具体数据流如下：

1. **用户操作：** 用户在EFIS控制面板上进行操作（如切换模式、调节范围）。
2. **事件处理：** 控制层捕获用户事件，调用对应的事件处理函数。
3. **状态更新：** 事件处理函数更新React状态（State），触发组件重新渲染。
4. **重新渲染：** NDDisplay组件根据更新后的状态重新绘制Canvas画面。

服务层的数据流则采用观察者模式（Observer Pattern）：

```
数据源 → Service → Listener → State Update → Re-render
```

例如，TCAS服务定期从数据源获取交通数据，计算威胁等级后通过监听器通知控制层更新状态。

### 4.1 ND显示模式实现

#### 4.1.1 ROSE NAV模式

ROSE NAV模式是ND最基本的显示模式，飞机位于显示器中心，航向朝上，显示完整的360°罗盘玫瑰。该模式的实现涉及以下关键技术：

**（1）罗盘玫瑰绘制**

罗盘玫瑰（Compass Rose）是ND的核心视觉元素，由同心圆环、角度刻度标记和方位标签组成。实现代码位于 [`utils/drawingUtils.js`](utils/drawingUtils.js:57) 的 `drawCompassRose` 函数：

```javascript
export const drawCompassRose = (ctx, cx, cy, radius, heading, mode = 'ROSE', range = 80) => {
  ctx.beginPath();
  ctx.arc(cx, cy, radius, 0, Math.PI * 2);
  ctx.strokeStyle = COLORS.COMPASS_WHITE;
  ctx.lineWidth = 2;
  ctx.stroke();
  for (let deg = 0; deg < 360; deg += 5) {
    const isMajor = deg % 10 === 0;
