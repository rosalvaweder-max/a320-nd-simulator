## 中文摘要

航空電子顯示系統是現代飛機駕駛艙的核心組成部分，其中導航顯示器（Navigation Display, ND）為飛行員提供關鍵的態勢感知資訊。本論文設計並實現了一套基於Web技術的A320導航顯示器模擬系統，採用React 19框架與HTML5 Canvas 2D渲染引擎，在瀏覽器環境中高保真地模擬了真實A320 ND的五種顯示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN）。系統採用三層模組化架構設計，涵蓋顯示層、控制層與服務層，實現了飛行計劃管理、VOR/ILS導航顯示、TCAS交通防撞系統、天氣雷達模擬、增強型近地警告系統（EGPWS）以及CRT/LCD顯示效果模擬等核心功能。針對Canvas渲染性能瓶頸，設計並實現了包含顯示列表快取、髒矩形管理與空間索引的三級性能優化策略，確保在複雜場景下維持30 FPS以上的流暢幀率。實驗結果表明，本系統在功能完整性、顯示真實性與運行性能方面均達到了預期目標，可作為航空電子教學訓練與飛行程序研究的有效工具。

## Abstract

Avionics display systems are core components of modern aircraft cockpits, among which the Navigation Display (ND) provides pilots with critical situational awareness information. This thesis designs and implements a web-based A320 Navigation Display simulator system, utilizing the React 19 framework and HTML5 Canvas 2D rendering engine to faithfully simulate five display modes (ROSE NAV, ROSE ILS, ROSE VOR, ARC, PLAN) of the real A320 ND in a browser environment. The system adopts a three-layer modular architecture covering the presentation layer, control layer, and service layer, implementing core functionalities including flight plan management, VOR/ILS navigation display, TCAS traffic collision avoidance system, weather radar simulation, Enhanced Ground Proximity Warning System (EGPWS), and CRT/LCD display effect simulation. To address Canvas rendering performance bottlenecks, a three-level performance optimization strategy incorporating display list caching, dirty rectangle management, and spatial indexing has been designed and implemented, ensuring a smooth frame rate above 30 FPS under complex scenarios. Experimental results demonstrate that the system achieves the expected goals in terms of functional completeness, display authenticity, and operational performance, serving as an effective tool for avionics education, training, and flight procedure research.

**Keywords:** A320 Navigation Display; Web Simulator; Canvas 2D Rendering; Avionics Systems; Flight Simulation

## 第一章 緒論

### 1.1 研究背景與意義

航空電子系統（Avionics）是現代民用航空器的核心組成部分，其發展水平直接影響飛行安全、運營效率與飛行員工作負荷。隨著航空技術的不斷進步，傳統的機電式飛行儀表已逐步被電子飛行儀表系統（Electronic Flight Instrument System, EFIS）所取代。在眾多民航機型中，空中巴士A320系列飛機作為全球最暢銷的單通道客機之一，其玻璃駕駛艙（Glass Cockpit）設計理念代表了現代民航機駕駛艙的典型架構，因此被選為本系統的模擬對象。

選擇A320作為模擬對象的原因如下：

**（1）市場佔有率與行業影響力：** A320系列飛機是全球範圍內運營數量最多的單通道客機之一，截至2025年已交付超過11,000架，全球超過300家航空公司運營該機型。龐大的運營基數意味著對A320相關訓練設備的持續需求，開發A320 ND模擬器具備廣泛的應用前景。

**（2）玻璃駕駛艙的代表性：** A320是全球首款大規模採用電傳操縱（Fly-by-Wire）技術與全玻璃駕駛艙的商用客機，其EFIS系統的設計理念深刻影響了後續所有機型（包括Boeing 777、B787、A350等）。掌握A320 ND的模擬技術，可為其他機型的模擬開發提供重要的技術參考。

**（3）技術資料的可獲取性：** 空中巴士公司公開了大量A320相關技術資料，包括飛行機組操作手冊（Flight Crew Operating Manual, FCOM）[1]、飛機維修手冊（Aircraft Maintenance Manual, AMM）[2]以及航空電子系統描述文件，為精確模擬提供了可靠的技術依據。

**（4）ND系統的完整性與複雜性：** A320 ND支援五種顯示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN），涵蓋從航路巡航到精密進近的全飛行階段顯示需求。其顯示邏輯涵蓋VOR/ILS導航、TCAS交通監控、天氣雷達、EGPWS地形感知等多個子系統，功能完整且具有適度的複雜性，既能體現航空電子系統的核心技術特徵，又能在Web環境中實現可控的模擬範圍。

**（5）教學與訓練價值：** A320 ND系統涵蓋了航空電子顯示系統的核心概念，包括坐標變換、符號生成、導航計算、多層次渲染等技術要點，是航空電子工程、計算機科學、自動化等非飛行專業學生理解航空電子系統工作原理的理想教學案例。基於Web的模擬器無需專用硬體設備，為非飛行專業學生提供了低成本、高可訪問性的實踐學習平台，有助於縮短理論教學與工程實踐之間的差距。

A320的導航顯示器（Navigation Display, ND）是EFIS系統的關鍵組成部分，位於駕駛艙正前方儀表板中央位置，為飛行員提供全面的導航態勢感知資訊。ND能夠以多種顯示模式呈現飛行計劃航路、導航輔助設備（VOR/NDB）、氣象雷達回波、交通防撞系統（TCAS）資訊以及地形感知資料，是飛行員進行航路監控、態勢判斷與決策制定的核心視覺介面。

然而，真實的A320 ND系統具有以下局限性：（1）造價昂貴，一台完整的ND訓練設備成本高達數十萬美元；（2）操作環境封閉，難以進行功能擴展與二次開發；（3）教學資源有限，非飛行專業學生難以接觸到真實的航空電子顯示設備。因此，開發一套基於Web技術的A320 ND模擬器具有重要的理論與實踐意義：

**（1）降低教學門檻：** 基於Web的模擬器無需專用硬體設備，僅需標準瀏覽器即可運行，大幅降低了航空電子教學的硬體門檻，使非飛行專業學生也能夠直觀地理解航空電子顯示系統的工作原理。

**（2）提高可訪問性：** Web應用的跨平台特性使得學生可以在任何具備瀏覽器的設備上進行學習與實驗，包括個人電腦、平板電腦等，突破了時間與空間的限制。

**（3）促進教學創新：** 開放的Web技術棧使得教師可以根據教學需要自定義實驗場景、修改顯示邏輯，為航空電子課程的理論教學與實驗環節提供了極大的靈活性。

**（4）技術驗證平台：** 本系統可作為航空電子新技術（如新型導航顯示格式、增強型態勢感知介面）的快速原型驗證平台，為航空電子工程相關專業的學生提供工程實踐環境。

### 1.2 國內外研究現狀

#### 1.2.1 國外研究現狀

在國際上，航空模擬器技術已發展較為成熟。以CAE、L3Harris、FlightSafety International為代表的專業模擬器製造商提供了從全任務模擬器（Full Flight Simulator, FFS）到桌面訓練設備（Desktop Training Device, DTD）的全系列產品。在開源與學術領域，X-Plane、Microsoft Flight Simulator等消費級飛行模擬平台提供了豐富的SDK與外掛程式介面，支援第三方開發者進行航空電子系統的模擬開發。

在ND模擬器方面，部分開源項目如OpenFlightSim、YASim等提供了基本的導航顯示功能，但通常存在以下不足：（1）顯示精度較低，符號系統與真實A320 ND存在較大差距；（2）功能不完整，缺乏TCAS、天氣雷達等高級功能；（3）性能優化不足，在複雜場景下幀率不穩定。

#### 1.2.2 國內研究現狀

國內在航空模擬器領域的研究起步較晚，但近年來發展迅速。北京航空航天大學、南京航空航天大學、中國民航大學等高校在飛行模擬器、航空電子系統模擬方面開展了大量研究工作。在Web-based航空模擬方面，部分研究嘗試利用HTML5技術實現飛行儀表的模擬，但多集中於主飛行顯示器（Primary Flight Display, PFD）的模擬，針對ND系統的完整模擬研究相對較少。

現有國內研究中，ND模擬器普遍存在以下問題：（1）顯示模式單一，通常僅實現ROSE NAV模式；（2）缺乏完整的VOR/ILS導航邏輯模擬；（3）未實現TCAS、天氣雷達等高級功能；（4）性能優化不足，無法滿足流暢交互的需求。

#### 1.2.3 現有研究的不足

綜合分析國內外研究現狀，現有ND模擬器研究存在以下主要不足：

1. **功能完整性不足：** 多數模擬器僅實現了基本的導航顯示功能，缺乏對TCAS、天氣雷達、EGPWS等高級功能的支援。
2. **顯示真實性有限：** 符號系統、顏色方案與真實A320 ND標準存在較大差距，影響訓練效果。
3. **性能優化欠缺：** 缺乏系統性的性能優化策略，在複雜場景下難以維持流暢的交互體驗。
4. **架構可擴展性差：** 模組化設計不足，新增功能需要大量修改既有代碼。

### 1.3 論文主要工作

本論文旨在設計並實現一套基於Web技術的高保真A320 ND模擬器，主要工作包括：

1. **系統架構設計：** 採用三層模組化架構，將系統劃分為顯示層、控制層與服務層，各層次職責清晰、耦合度低，支援功能擴展與維護。

2. **五種ND顯示模式實現：** 完整實現ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN五種顯示模式，每種模式均遵循真實A320 ND的顯示邏輯與符號標準。

3. **導航計算引擎：** 實現VOR徑向偏差計算、ILS航向道/下滑道偏差計算、弧形過渡幾何模型等核心導航演算法。

4. **高級功能系統：** 實現TCAS交通防撞系統（含RA/TA威脅等級評估）、天氣雷達模擬（含四級降水強度與湍流檢測）、增強型近地警告系統（EGPWS）等功能。

5. **性能優化系統：** 設計並實現顯示列表快取、髒矩形管理、空間索引三級性能優化策略，確保複雜場景下的流暢渲染。

6. **顯示效果系統：** 實現CRT/LCD/OLED等多種顯示效果模擬，包括掃描線、螢光輝光、像素網格、環境光影響等。

## 第二章 相關技術與理論基礎

### 2.1 A320導航顯示器系統概述

#### 2.1.1 ND系統功能與架構

A320導航顯示器（ND）是電子飛行儀表系統（EFIS）的重要組成部分，位於駕駛艙正前方儀表板中央位置。ND的主要功能是為飛行員提供全面的導航態勢感知資訊，包括飛行計劃航路顯示、導航輔助設備定位、氣象雷達回波、交通防撞資訊以及地形感知資料。

ND系統的輸入來源包括：（1）飛行管理引導系統（Flight Management and Guidance System, FMGS），提供飛行計劃資料與導航計算結果；（2）慣性參考系統（Inertial Reference System, IRS），提供飛機姿態與位置資訊；（3）大氣資料慣性基準系統（Air Data Inertial Reference System, ADIRS），提供空速、高度等大氣資料；（4）導航接收機（VOR/ILS/DME接收機），提供無線電導航資訊；（5）氣象雷達接收機，提供天氣回波資料；（6）TCAS電腦，提供交通監控資訊。

#### 2.1.2 五種顯示模式

A320 ND支援五種顯示模式，每種模式適用於不同的飛行階段與任務需求：

**（1）ROSE NAV模式：** 全羅盤玫瑰導航模式，飛機位於顯示器中心，航向朝上。顯示完整的360°羅盤玫瑰、飛行計劃航路、航路點、導航輔助設備等資訊。適用於航路巡航階段的導航監控。

**（2）ROSE ILS模式：** 儀表著陸系統模式，在ROSE NAV顯示的基礎上疊加ILS航向道（LOC）與下滑道（GS）偏差指示。適用於精密進近階段的引導。

**（3）ROSE VOR模式：** VOR導航模式，在ROSE NAV顯示的基礎上疊加VOR航道偏差指示器（CDI），包括航道桿、偏離桿、TO/FROM標誌等。適用於VOR導航與非精密進近。

**（4）ARC模式：** 弧形顯示模式，飛機位於顯示器底部中心，顯示前方約100°~140°扇形空域。航向朝上，顯示飛行計劃航路與導航資訊。適用於航路監控與進近階段。

**（5）PLAN模式：** 計劃模式，北向上固定方位，以目標航路點為中心顯示完整的飛行計劃航路。不顯示飛機即時位置，適用於航路規劃與審查。

#### 2.1.3 顏色標準與符號系統

A320 ND採用標準化的顏色編碼系統，以確保資訊傳遞的一致性和可讀性：

- **洋紅色（Magenta）：** 表示主動飛行計劃、選定資料、主動航段
- **青色（Cyan）：** 表示飛行計劃航路、航路點、導航輔助設備
- **綠色（Green）：** 表示主動航段、航跡線
- **黃色（Yellow）：** 表示飛機符號、注意指示
- **琥珀色（Amber）：** 表示警告、建議
- **紅色（Red）：** 表示警報、故障

### 2.2 Web前端技術棧

#### 2.2.1 React 19框架

React是由Meta（原Facebook）開發的用於構建使用者介面的JavaScript函式庫。React 19作為最新穩定版本，引入了多項重要特性：

- **並發模式（Concurrent Mode）：** 允許React中斷長時間運行的渲染任務，優先處理高優先順序更新，提升使用者體驗。
- **伺服器元件（Server Components）：** 支援在伺服器端渲染元件，減少用戶端JavaScript體積。
- **改進的Suspense機制：** 提供更優雅的非同步資料載入處理方式。

在本系統中，React 19被選為UI框架的主要原因包括：（1）元件化開發模式，便於模組化架構的實現；（2）虛擬DOM機制，減少實際DOM操作次數；（3）豐富的生態系統與社群支援。

#### 2.2.2 Vite 5構建工具

Vite是一個現代化的前端構建工具，利用原生ES模組（ESM）實現開發伺服器的快速啟動與熱模組替換（HMR）。Vite 5在以下方面表現優異：

- **極速冷啟動：** 基於ESM的開發伺服器無需打包，啟動速度遠快於Webpack等傳統工具。
- **高效的HMR：** 模組級別的熱更新，修改代碼後僅重新編譯受影響的模組。
- **優化的生產構建：** 基於Rollup的生產構建，支援代碼分割（Code Splitting）與樹搖（Tree Shaking）。

#### 2.2.3 ES Modules模組化

本系統採用ES Modules（ESM）作為模組化方案，利用`import`與`export`語句實現模組的載入與匯出。ESM具有以下優勢：

- **靜態分析：** 編譯時即可確定模組的依賴關係，支援樹搖優化。
- **非同步載入：** 支援動態`import()`實現按需載入。
- **嚴格的模組作用域：** 每個模組擁有獨立的作用域，避免全域變數污染。

### 2.3 Canvas 2D渲染技術

#### 2.3.1 Canvas API概述

HTML5 Canvas提供了一個基於像素的2D繪圖表面，通過JavaScript API進行圖形繪製。Canvas 2D渲染管線包括以下主要步驟：

1. **獲取渲染上下文：** 通過`canvas.getContext('2d')`獲取2D渲染上下文。
2. **設置繪圖狀態：** 設置線條樣式（`strokeStyle`）、填充樣式（`fillStyle`）、線寬（`lineWidth`）、變換矩陣（`transform`）等。
3. **定義路徑：** 使用`beginPath()`、`moveTo()`、`lineTo()`、`arc()`等方法定義繪圖路徑。
4. **執行繪製：** 使用`stroke()`或`fill()`方法執行實際繪製。
5. **狀態保存與恢復：** 使用`save()`與`restore()`方法管理繪圖狀態棧。

#### 2.3.2 Canvas性能優化策略

Canvas 2D渲染的性能瓶頸主要來自於：（1）大量繪圖呼叫導致的CPU開銷；（2）像素操作（如`getImageData`/`putImageData`）的記憶體頻寬消耗；（3）Canvas尺寸過大導致的GPU記憶體壓力。

針對上述瓶頸，常見的優化策略包括：

- **離屏Canvas快取：** 將靜態內容（如羅盤玫瑰、範圍環）渲染到離屏Canvas，主Canvas僅渲染動態內容。
- **分層渲染：** 將不同類型的內容（如背景、航路、動態元素）分配到不同的Canvas圖層，減少重繪面積。
- **髒矩形更新：** 僅重繪發生變化的區域，而非整個Canvas。
- **請求動畫幀（requestAnimationFrame）：** 使用瀏覽器提供的動畫幀機制，避免不必要的渲染。

### 2.4 導航計算理論基礎

#### 2.4.1 座標系統與變換

本系統涉及多個座標系統的轉換：

**（1）地理座標系（經緯度）：** 使用WGS-84橢球模型，以經度（λ）和緯度（φ）表示位置。

**（2）笛卡爾座標系（Canvas座標）：** 以像素為單位，x軸向右，y軸向下。

**（3）ND顯示座標系：** 以顯示器中心為原點，x軸向右，y軸向上（與Canvas座標系y軸方向相反）。

座標轉換流程如下：

```
地理座標(λ, φ) → 平面投影(x, y) → 螢幕座標(sx, sy)
```

其中，平面投影採用等距方位投影（Azimuthal Equidistant Projection），以飛機位置為投影中心。

#### 2.4.2 VOR導航原理

VOR（Very High Frequency Omnidirectional Range）是一種基於地面台的短程無線電導航系統。VOR台發射兩個信號：（1）一個全向參考信號；（2）一個旋轉方向性信號。機載接收機通過比較兩個信號的相位差來確定相對於VOR台的徑向方位。

VOR導航的核心計算包括：

**（1）徑向方位計算：** 飛機相對於VOR台的方位角，計算公式為：

```
θ = atan2(Δx, Δy)
```

其中Δx和Δy為飛機相對於VOR台的笛卡爾座標差。

**（2）航道偏離計算：** 飛機當前徑向與選定航道之間的角度差：

```
deviation = selectedRadial - aircraftRadial
```

**（3）TO/FROM判斷：** 根據飛機相對於選定航道的位置判斷：

- TO：飛機位於選定航道的來向方向
- FROM：飛機位於選定航道的去向方向

#### 2.4.3 ILS導航原理

ILS（Instrument Landing System）是一種精密進近引導系統，由三個部分組成：

**（1）航向台（Localizer, LOC）：** 提供橫向引導，發射方向性信號，在跑道中心延長線上形成航向道。

**（2）下滑台（Glideslope, GS）：** 提供垂直引導，發射方向性信號，形成標準的3°下滑角。

**（3）指標台（Marker Beacons）：** 提供距離跑道入口的距離參考。

ILS偏差計算：

```
locDeviation = (aircraftBearing - locCourse) / locFullScale
gsDeviation = (aircraftElevationAngle - gsAngle) / gsFullScale
```

其中，locFullScale通常對應±0.5°（2點偏差），gsFullScale通常對應±0.7°。

#### 2.4.4 弧形過渡幾何模型

在飛行計劃中，當飛機從一個航段過渡到另一個航段時，需要沿弧形路徑轉彎。弧形過渡的幾何計算包括：

**（1）轉彎半徑計算：**

```
R = V² / (g × tan(φ))
```

其中V為真空速，g為重力加速度，φ為坡度角。

**（2）弧形參數計算：**

- 圓心座標：根據入航航向、出航航向和轉彎半徑計算
- 起始角度：入航航向對應的圓弧起始點
- 終止角度：出航航向對應的圓弧終止點
- 轉彎方向：左轉或右轉

**（3）弧形插值：** 在圓弧上按角度步長採樣，計算每個採樣點的位置與瞬時航向（圓弧切線方向）。

3. **狀態更新：** 事件處理函數更新React狀態（State），觸發元件重新渲染。
4. **重新渲染：** NDDisplay元件根據更新後的狀態重新繪製Canvas畫面。

服務層的資料流則採用觀察者模式（Observer Pattern）：

```
資料源 → Service → Listener → State Update → Re-render
```

### 4.1 ND顯示模式實現

#### 4.1.1 ROSE NAV模式

ROSE NAV模式是ND最基本的顯示模式，飛機位於顯示器中心，航向朝上，顯示完整的360°羅盤玫瑰。該模式的實現涉及以下關鍵技術：

**（1）羅盤玫瑰繪製**

羅盤玫瑰（Compass Rose）是ND的核心視覺元素，由同心圓環、角度刻度標記和方位標籤組成。實現程式碼位於 [`utils/drawingUtils.js`](utils/drawingUtils.js:57) 的 `drawCompassRose` 函數：

```javascript
export const drawCompassRose = (ctx, cx, cy, radius, heading, mode = 'ROSE', range = 80) => {
  ctx.beginPath();
  ctx.arc(cx, cy, radius, 0, Math.PI * 2);
  ctx.strokeStyle = COLORS.COMPASS_WHITE;
  ctx.lineWidth = 2;
  ctx.stroke();
  for (let deg = 0; deg < 360; deg += 5) {
    const isMajor = deg % 10 === 0;
    const isCardinal = deg % 30 === 0;
    const angle = (deg - heading + 360) % 360;
    const rad = angle * Math.PI / 180;
    const innerR = isCardinal ? radius - 20 : isMajor ? radius - 12 : radius - 8;
    // 繪製刻度線
  }
```

```javascript
  const dx = aircraft.x - vorStation.x;
  const dy = aircraft.y - vorStation.y;
  const bearing = (Math.atan2(dx, dy) * 180 / Math.PI + 360) % 360;
  let deviation = selectedCourse - bearing;
```

```javascript
const calculateILSDeviation = (aircraft, ilsStation) => {
  const locCourse = ilsStation.locCourse;
  const dx = aircraft.x - ilsStation.x;
  const dy = aircraft.y - ilsStation.y;
  const bearing = (Math.atan2(dx, dy) * 180 / Math.PI + 360) % 360;
  let locDeviation = bearing - locCourse;
  if (locDeviation > 180) locDeviation -= 360;
  if (locDeviation < -180) locDeviation += 360;
  const normalizedLocDev = Math.max(-1, Math.min(1, locDeviation / 0.5));
  
  const gsAngle = 3;
  const distance = Math.sqrt(dx * dx + dy * dy);
  const elevationAngle = Math.atan2(aircraft.altitude - ilsStation.elevation, distance * 6076);
  const gsDeviation = (elevationAngle * 180 / Math.PI - gsAngle) / 0.7;
  return { locDeviation: normalizedLocDev, gsDeviation };
};
```

#### 4.7.3 空間索引（Spatial Index）

空間索引基於網格劃分實現高效的空間查詢，將查詢複雜度從O(n)降低到O(1)：

```javascript
class SpatialIndex {
  constructor(cellSize = 100) { this.cellSize = cellSize; this.grid = new Map(); }
  add(id, x, y, width, height) {
    const keys = this.getGridKeys(x, y, width, height);
    keys.forEach(key => {
      if (!this.grid.has(key)) this.grid.set(key, new Set());
      this.grid.get(key).add(id);
    });
  }
  query(x, y, width, height) {
    const keys = this.getGridKeys(x, y, width, height);
    const result = new Set();
    keys.forEach(key => {
      if (this.grid.has(key)) this.grid.get(key).forEach(id => result.add(id));
    });
    return [...result];
  }
  getGridKeys(x, y, width, height) {
    const keys = [];
    const minCol = Math.floor(x / this.cellSize);
    const maxCol = Math.floor((x + width) / this.cellSize);
    const minRow = Math.floor(y / this.cellSize);
    const maxRow = Math.floor((y + height) / this.cellSize);
    for (let col = minCol; col <= maxCol; col++)
      for (let row = minRow; row <= maxRow; row++)
        keys.push(`${col},${row}`);
    return keys;
  }
}
```

```javascript
class FrameRateController {
  constructor(targetFPS = 60) {
    this.targetFPS = targetFPS;
    this.frameInterval = 1000 / targetFPS;
    this.lastFrameTime = 0;
  }
  async throttle() {
    const now = performance.now();
    const elapsed = now - this.lastFrameTime;
    if (elapsed < this.frameInterval) {

    }
    this.lastFrameTime = performance.now();
```

## 第六章 結論與展望

### 6.1 論文總結

本論文圍繞基於Web技術的A320導航顯示器模擬器的設計與實現展開研究，完成了一套功能完整、性能優越、顯示真實的ND模擬系統。論文的主要工作與成果總結如下：

**（1）系統架構設計：** 採用三層模組化架構（顯示層、控制層、服務層），實現了各功能模組的低耦合設計。顯示層基於React 19框架與HTML5 Canvas 2D渲染引擎，控制層通過React Context機制實現狀態管理，服務層封裝了TCAS、天氣雷達、地圖資料等業務邏輯。

**（2）五種ND顯示模式實現：** 完整實現了ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN五種顯示模式。每種模式均遵循真實A320 ND的顯示邏輯與符號標準，包括羅盤玫瑰繪製、地圖投影與座標變換、ILS航向道/下滑道偏差指示、VOR航道偏差指示器（CDI）、弧形視口計算等關鍵技術。

**（3）導航計算引擎：** 實現了VOR徑向偏差計算、ILS航向道/下滑道偏差計算、弧形過渡幾何模型等核心導航演算法。VOR模式採用五階段流水線架構，支援平滑航道過渡與三級VOR台檢測優先級。

**（4）高級功能系統：** 實現了TCAS交通防撞系統（含RA/TA/PROXIMATE/OTHER四級威脅評估）、天氣雷達模擬（含五種天氣模式與四級降水強度顏色編碼）、增強型近地警告系統（EGPWS，含地形等高線繪製與淨空計算）。

**（5）性能優化系統：** 設計並實現了顯示列表快取、髒矩形管理、空間索引三級性能優化策略。測試結果表明，三級優化策略在複雜場景下將幀率從15 FPS提升至38 FPS，提升幅度達153%。

**（6）顯示效果系統：** 實現了CRT/LCD/OLED等多種顯示器效果模擬，以及日光沖刷、夜間調暗、雨滴效果等環境效果模擬，顯著增強了ND顯示的真實感。

### 6.2 主要貢獻

本論文的主要貢獻體現在以下幾個方面：

1. **提出了一套完整的Web-based ND模擬器架構方案：** 該方案基於React 19 + Vite 5 + Canvas 2D技術棧，為航空電子顯示系統的Web模擬提供了一個可複用的技術框架。

2. **設計了VOR模式五階段流水線架構：** 將VOR顯示的計算過程分解為五個獨立階段，消除了重複計算，提高了VOR模式的運行效率。

3. **實現了三級Canvas性能優化策略：** 針對Canvas 2D渲染的性能瓶頸，提出了顯示列表快取、髒矩形管理、空間索引相結合的優化方案，為Web-based航空顯示系統的性能優化提供了參考。

4. **建立了完整的測試評估體系：** 從功能完整性、顯示真實性、運行性能三個維度對系統進行了全面評估，並與同類系統進行了對比分析。

### 6.3 未來工作展望

儘管本系統已實現了A320 ND的核心功能，但與真實ND系統相比仍存在一定差距。未來的研究工作可從以下幾個方向展開：

**（1）功能完善：** 實現ADF指示器、TTG/DTW/ETA計算引擎、風數據集成、垂直導航（VNAV）等缺失功能，進一步縮小與真實ND的功能差距。

**（2）模擬器集成：** 完善與X-Plane、MSFS2020等外部飛行模擬器的集成介面，實現真實飛行數據的輸入，提升模擬的真實性。

**（3）三維顯示支援：** 探索WebGL/Three.js在三維航空顯示中的應用，實現三維地形顯示與合成視景系統（Synthetic Vision System, SVS）。

**（4）多人協同訓練：** 基於WebSocket實現多人協同訓練功能，支援教員-學員互動模式。

**（5）移動端適配：** 優化系統在移動設備（平板電腦）上的顯示與交互體驗，擴展訓練場景。

**（6）人工智能輔助：** 引入機器學習演算法，實現智慧飛行路徑規劃與異常檢測功能。
