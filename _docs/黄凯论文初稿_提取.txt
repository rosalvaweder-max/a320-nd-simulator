摘  要

航空电子显示器系统是现代飞机驾驶舱的核心组成系统，其中飞机导航显示器系统是其中的重要组成部分，是飞行员获取飞机位置，飞行导航信息和周边环境信息的重要途径。本设计通过以空客A320系列飞机的ND系统为参考，设计并实现了一个基于网页的飞机导航显示器模拟器系统。本设计旨在提供一个帮助学生学习理解导航显示器的工具，在导航原理等相关课程中辅助理论教学。

本文主要分析了研究背景和研究现状，介绍了A320 ND的五种显示模式（ROSE NAV,ROSE ILS,ROSE VOR,ARC PLAN），确认了本设计需要实现的核心功能。然后论述模拟器五种显示模式具体的功能表现形式和实现方法，最后论述了网页模拟的最终呈现形式和效果演示。

本设计基于React框架与HTML5 Canvas 2D渲染引擎，实现了A320 ND的五种显示模式（ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN）及模式切换逻辑，完成了EFIS控制面板的交互设计、飞行计划航路管理、VOR/ILS导航引导显示等功能。经测试验证，各模式显示正确、交互响应正常、运行性能流畅。本设计可为航空电子设备教学提供一种低成本、跨平台的辅助工具。

关键词：飞机导航显示器，A320，网页模拟，教学辅助工具



ABSTRACT

The avionics display system is a core component of the modern aircraft cockpit, among which the aircraft Navigation Display (ND) system is an important part, serving as a crucial means for pilots to obtain aircraft position, flight navigation information, and surrounding environmental information. This paper presents a web-based aircraft navigation display simulator referenced from the ND system of the Airbus A320 series aircraft, designing and implementing a web-based aircraft navigation display simulator system. This design aims to provide a tool to help students learn and understand the navigation display, assisting theoretical teaching in courses such as navigation principles.

This paper mainly analyzes the research background and current research status, introduces the five display modes of the A320 ND (ROSE NAV, ROSE ILS, ROSE VOR, ARC, PLAN), and identifies the core functions that need to be implemented in this design. It then discusses the specific functional presentation forms and implementation methods of the simulator's five display modes, and finally discusses the final presentation form and effect demonstration of the web-based simulation.

This aircraft navigation display simulator design implements display simulation based on the five display modes of the A320 ND, supporting mode switching via the control panel, flight plan route management, VOR navigation guidance, and other functions. Test results verify that each mode displays correctly, interaction responses are normal, and operational performance is smooth. This design can provide a low-cost, cross-platform teaching aid for avionics education.

Keyword: Aircraft Navigation Display, A320, Web-based Simulation, Teaching Aid

绪论

本章首先介绍航空电子系统的发展背景与A320导航显示器模拟器的研究意义，明确本论文的研究目标。通过分析真实A320系统在课堂教学中的局限性，论证开发网页ND显示器模拟器的实用价值。同时通过分析国内外航空模拟器的研究现状，从多个方面分析现有模拟系统的不足之处，明确本设计的创新方向，最后简述论文的主要内容与整体结构。

研究背景

航空电子系统（Avionics）是现代民用航空器的核心组成部分，其可靠性将直接影响飞行安全。在众多民航机型中，空客A320作为全球使用最广泛的客机之一，作为一款大规模采用电传操纵技术的客机，尤其是典型的EFIS系统设计理念，具有优秀的参考意义[1]。其中A320 ND可支持五种显示模式覆盖从巡航到进近的全飞行阶段的显示需求，功能完整，能体现ND显示系统的技术特征[2]。

A320 ND系统涵盖了航空电子显示系统的核心设计理念，包括坐标变换，符号生成，导航计算等内容[3]。A320 ND是民航院校电子信息工程，自动化等非飞行专业学习导航原理的理想教学模型[4]。随着智能化和数字化技术的发展，网页技术在民航教育和民航知识普及具有广泛的应用前景，而本设计可以帮助非飞行学生在没有专业设备的情况下，更直观的理解学习导航显示器的内容，有助于理论和实际相结合的学习。

此外，飞机导航显示器模拟器设计，基于网页的模拟器无需专业硬件设备，为学生提供了一个低成本，便于访问的学习平台。同时该设计还可以作为教学工具，有助于教师更好的教学，也为其他民航方面的知识教学提供了一个新的教学方式。

研究现状

航空模拟器用于飞行训练、航空器研发和事故调查，它一直把高保真度、实时性和物理逼真度为主要目标。在技术实现方面，传统航空模拟器一般采用C/C++这类编程语言，利用专业图形库来进行开发，并且依靠专用硬件设备例如飞行模拟机能够用来完成完整的飞行环境仿真。这些平台在专业飞行训练和工程验证领域被广泛使用，能够达到飞行员机型训练和航空器适航测试的要求。本文对空客A320机型的导航显示器进行模拟，国内和国外部分研究项目已经尝试模拟并复现ND界面[5]。这些工作主要集中在两个方面，一方面是基于传统模拟器平台开发ND模块，并利用X-Plane或Flight Gear的SDK来完成ND数据的读取和显示[6]。二是使用通用图形库的独立ND演示程序，依靠预先录制的数据或者简单数学模型来驱动界面动画。

不过，前面提到的传统模拟器方法存在一些缺陷：首先，部署工作比较复杂，通常要依靠高性能的软件和硬件来支持，安装和配置过程比较麻烦。其次，对特定操作系统的依赖性较强，跨平台能力有限。第三，硬件成本较高，一套完整的桌面模拟器硬件成本经常超过数万元，这使它在教学演示和大众化普及场景中的推广受到限制。

现有研究在航空导航显示器仿真方面主要进行专业硬件模拟，虽然技术已经成熟，但是部署成本和使用门槛限制了该技术在教学和科普场景中的推广。在Web轻量化仿真方面，现有成果主要集中于通用仪表，还没有实现对A320 ND这类复杂系统的深度模拟[7]。多数系统缺乏教学讲解功能、不能让用户自定义航路、不支持模式切换的ND模拟器[8]。本文打算利用网页前端技术，形成一套依靠网页的A320飞机导航显示器模拟器[9]。该系统会实现A320导航显示器不同模式的显示和切换逻辑，把自动注释讲解功能集成进来以支持教学使用，并且支持用户自定义地图数据导入的完整模拟系统，最后成为一个低门槛和跨平台的航空教学工具。

1.分析五种ND显示模式：完整实现ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN五种显示模式，每种模式都应遵循真实A320 ND的显示逻辑与显示形式。ROSE NAV模式显示以飞机为中心的360°导航信息；ROSE ILS模式显示ILS航向道偏差与下滑道偏差，ROSE VOR模式显示VOR台方位指示和CRS航道和偏离指示；ARC模式显示前方90°扇形导航显示；PLAN模式显示以下一航路点为中心的导航信息。

A320导航显示器系统与导航理论分析

本章整体说明A320导航显示器ND的工作原理、导航器开发所需要的航空计算理论基础，给后面系统设计和实现提供理论支持。本文首先对A320ND系统的功能模式进行分析，然后对五种显示模式ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN的工作原理和显示标准进行分析，最后对EFIS控制面板的交互方式进行分析，为后续的系统设计提供理论基础。

导航显示器系统功能

A320导航显示器位于驾驶舱正前方仪表面板中央位置，ND的主要功能是为飞行员提供全面的导航资讯，包括航道偏离指示、VOR台信息、计划航路、航路点信息、飞行航向等。在飞行过程中，飞行员可以按需要选取不同显示模式来获取不同的导航信息。导航显示器的五种显示模式如下[11]：

(1)ROSE NAV模式：全罗盘显示导航模式，飞机位于显示器中心，航向朝上。显示完整的360°罗盘、飞行计划航路、航路点等导航信息。主要适用于巡航阶段的导航监控。

（2）ROSE ILS模式：仪表着陆系统模式，该模式显示ILS信息、水平航向道（LOC）偏差和垂直下滑道（GS）偏差指示等信息。适用于精密进近阶段的引导。

（3）ROSE VOR模式：VOR导航模式，该模式显示VOR方位杆、VOR航道杆、向背台标识、航道偏离杆以及对应的VOR信息。适用于以VOR为基础的导航。

（4）ARC模式：扇形显示模式，该模式与罗盘NAV模式提供相同的信息，但在ARC模式下只显示前方90°扇形区，主要用于查看气象雷达系统提供的气象信息。

（5）PLAN模式：计划模式，以北向上固定方位，以目标航路点为中心显示完整的飞行计划航路，主要用于检查飞行计划航路。

导航显示器的显示参数和符号

A320 ND的五种显示模式满足了飞机从航路巡航到精密进近的全飞行阶段显示需求[12]。每个模式在显示布局、坐标系统和显示符号各有不同和特点，下面为详细内容。

首先，有一部分导航信息会在所有显示模式下显示，不会随着模式的切换而变化。下面内容介绍了一部分重要的显示信息，会在多模式显示。如黄色飞机符号，该符号是所有模式都会显示的，其中长横线表示机翼，短横线表示尾翼，位于显示中央指向黄色标线。然后是飞机航向指示，用固定的黄色标线在白色移动罗盘上指向飞机磁航向。罗盘，固定在屏幕中央，与不同模式的显示元素相互配合，指示各种方位信息，外侧有固定的小白三角置于罗盘周围，间隔为45°。选择的航向或航迹用蓝色指针表示。飞机的实际航迹用绿色小菱形表示。地速（Ground Speed）和真空速（Ture Air Speed）由ADIRS(大气数据惯性基准系统)提供，用绿色的字符显示在屏幕左上角[13]。风向及风速，数字方向和模拟方向（绿色箭头显示）都反映真北基准，由ADIRS提供显示在地速和真空速的下方。距离范围圈标识，表示当前选择的显示范围，可以通过在EFIS控制面板上所选的距离刻度值（10到320nm）控制ND的刻度范围。

同时，每种显示模式也有专门的导航信息，只在该模式下显示，以满足该模式需要实现的具体功能。在ROSE ILS模式下，会显示ILS航道指针和航向道偏离杆。ILS航道指针是洋红色剑形符号指向所选ILS航道,ILS航道由FMGC选择，如果没有选择输入航道则默认输入为360°。洋红色航向道偏离杆相对航道指针水平移动。偏离杆两侧各有两个刻度，偏离时通过读取刻度值来判断，每个刻度代表0.8°的偏离。还有代表下滑道偏离的洋红色菱形在屏幕右侧显示，刻度由中间黄色短横和上下四个白点组成，每个白点代表约0.4°的偏离。屏幕右上角显示选择的ILS信息，包含第一排的洋红色ILS频率，第二排的蓝色选择航道及第三排的洋红色识别码。

当选择ROSE VOR模式时，会出现蓝色VOR航道指针和水平偏离杆，指向所选的VOR航道和指示偏离。偏离杆相对航道指针水平移动，每个刻度代表5°，同样的VOR航道也可由FMGC自动选择或者人工选择。同时VOR模式显示两个不同的方位指针分别指示VOR1和VOR2。白色VOR信息包括所选VOR频率、选择航道和识别码同样会显示在屏幕的右上角。在屏幕的左下角和右下角会分别显示飞机1号接收机和2号接收机接收到的导航台类型、识别代码、调谐方式和距离信息。

介绍EFIS控制面板

EFIS控制面板是飞行员进行导航显示器系统交互的核心区域，位于驾驶舱遮光板上侧。本系统在设计EFIS控制面板时，充分参考了真实布局与操作逻辑，同时根据需要进行了合理的更改和简化，保证了操作的便捷性和功能的完整性。

模式选择旋钮是控制切换导航显示器模式的核心组件，控制实现导航显示器五种功能之间的切换。进行模式切换时，导航显示器会自动显示该模式的导航信息。导航模式选择旋钮旁边就是范围选择旋钮，用于调整导航显示器的显示范围以及显示数据，共支持调节10NM、20NM、40NM、80NM、160NM、320NM，共六个挡位的调节。

除了以上两个主要控制旋钮外，本设计还结合模拟器实际实现功能，添加了地形显示、气象显示、故障模拟等简单的功能呈现。

VOR调谐控制区域位于EFIS控制面板的右侧，用于控制VOR接收机的调谐状态。在本模拟器设计中添加了调谐模式切换按钮，用于自动调谐和手动调谐的切换。自动模式下VOR模式自动寻找锁定飞行计划航路中的VOR台；手动模式下可以通过频率调节旋钮来手动选择VOR台。

航路管理模块

航路管理模块是导航系统的核心功能之一，负责管理飞行计划，需要满足飞行航路的创建、修改、存储和切换功能[14]。航路管理模块在本设计中是实现用户自定义导入和修改航路信息的主要途径。

在本模拟器设计中，航路管理功能以按钮的形式放置在屏幕右侧EFIS控制面板下方，点击后显示航路列表和航路管理器，用户可以在这个界面编辑计划航路和编辑航路点信息。同时添加自定义地图导入功能，通过导入JSON格式文件，航路管理模块可以自动导入航路信息，并支持相应的编辑操作。为使用者提供了灵活简易的航路规划方式，在使用和交互方面有很大的改进。

网页前端技术

React是mate开发的用于建立用户界面的JavaScript库。React 19属于最近发布的稳定版本，该版本包括若干重要特点[15]。例如并发模式：React能够停止长时间进行的渲染工作，并且把高优先级的更新放在前面，以此来改善用户的体验。服务器组件：可以在服务器端进行组件渲染，从而减少客户端JavaScript的体积。Suspense模式在经过改进之后，拥有了更加完整的异步数据加载处理方式。本文选择React 19作为该系统UI框架的主要原因是：（1）组件化开发模式：模块化架构的实现比较方便，本文把ND显示、EFIS控制面板、飞行计划管理等重要功能封装成独立的React组件，各个组件可以独立进行编辑。（2）虚拟DOM方式：减少对实际DOM进行操作的次数，使页面响应速度得到提高。（3）Context API：本文通过使用FlightPlanContext.js和VORManagerConex.js，实现了飞行计划和VOR导航状态的全局共享，该方式减少了多层props传递所造成的代码冗余。

Vite是一个现代化的前端构建工具，利用原生ES模块实现开发服务器的快速启动与热模块替换[16]。Vite 5在以下方面表现优异:(1)快速冷启动：基于ESM的开发服务器无需打包，启动速度远快于Webpack等传统工具。在本系统中，执行<npm run dev>后开发服务器可在1秒内完成启动。（2）高效的HMR：模块级别的热更新，修改代码后仅需重新编译受影响的模块。在使用Canvas绘图函数时，修改<drawingUtils.js>中的绘图函数，浏览器会自动更新Canvas画面，无需手动刷新。（3）优化的生产构建：基于Rollup的生产构建，支持代码分割与树摇。本系统的<vite.config.js>配置了Vite的构建选项，减小生产构建后的输出文件体积。

HTML5 Canvas提供了一个基于像素的2D绘图表面，通过JavaScript API进行图形绘制[17]。Canvas 2D渲染管线包括以下主要步骤[18]：

1. 获取渲染上下文：通过canvas.getConext(2d)获取2D渲染上下文。

2.设置绘图状态：设置线条样式、填充样式、线宽、变换矩阵等。

3.定义路径：使用beginPath()、moveTo()、lineTo()、arc()等方法定义绘图路径。

4.执行绘制：使用stroke()或者fill()方法执行绘制。

5. 状态保存与恢复：使用save()与restore()方法管理绘图状态。

在本系统中，Canvas 2D API被广泛应用于ND画面的各个元素绘制。例如，方位罗盘的绘制、飞机符号的绘制、绘制范围圈等都使用了该技术。

本系统的代码采用JavaScript编写，选择JavaScript作为本系统的开发语言，主要基于其在Web开发领域的以下优势：

浏览器原生支持，不需要编译或插件：JavaScript是浏览器可以原生支持的脚本语言，不需要安装任何编译器、运行时环境或第三方插件就可以直接执行。该系统全部代码包括React组件逻辑、Canvas绘图指令、服务层业务逻辑都使用JavaScript编写，用户打开浏览器便可以运行整个ND模拟器。该便捷性使该系统拥有很高的可移植性和使用便利性，用户不用下载安装任何软件，只要访问网页链接就能使用完整的ND模拟功能。

事件驱动和异步编程模式：JavaScript使用事件驱动的编程方式，并且依靠单线程的事件循环方法，可以对用户交互、网络请求、动画渲染等各种并发任务进行处理。浏览器会在每次进行屏幕刷新前自动调用回调函数，该函数可以让Canvas渲染和显示器刷新率保持同步，一般设定为60Hz，这样做能够避免CPU出现不必要的占用、画面缺失的情况。用户在对EFIS面板进行操作时，例如切换模式和调节旋钮，会利用事件监听器来进行异步处理，这种方式不会阻塞动画循环的执行。

动态类型和灵活的数据处理：JavaScript属于动态类型语言，变量不需要进行类型声明就能使用，该特点在处理航空。电子系统里复杂多变的数据结构上比较方便。比如，VOR台站数据、飞行计划航路点数据、TCAS交通目标数据等。这些数据都可以通过普通JavaScript对象来进行灵活表示。开发者不需要定义复杂的接口或者进行类型声明，就可以快速地建立和迭代数据结构，这大幅度提高开发效率。

JSON原生支持：JSON是JavaScript原生支持的数据交换格式。本系统的地图数据、航路数据、VOR台站数据均以JSON格式存储和传输。JSON与JavaScript对象之间的无缝转换，使得本系统能够轻松处理来自JSON文件的地图数据.

本章就系统实现的角度，具体说明了A320导航显示器模拟器各功能模块的实现方式。实现介绍网页包括的静态内容的搭建方法，包括HTML页面结构、Canvas画布初始化和样式布局。然后说明动态内容的实现方式，包括React状态管理、数据控制和动画循环。接下来对五种ND显示模式，包括NAV、ILS、VOR、ARC、PLAN的Canvas绘制逻辑和实现进行分析。本文介绍EFIS控制面板的组件设计和交互实现，然后说明航路管理系统的状态管理和功能服务实现。

网页静态内容的制作

本系统采用单页面应用架构，所有界面元素通过React动态渲染。页面标题、窗口设置与数据在HTML头部定义，确保在不同屏幕尺寸下的正确显示。

ND显示区域的核心是HTML5 Canvas元素在界面中创建并初始化。画布尺寸固定为600×600像素，通过CSS进行缩放适配。在组件挂载发生变化时触发重新绘制。在绘制函数中首先计算画布中心坐标，然后根据画布高度确定罗盘半径，最后通过量程值计算每海里对应的像素数，该值决定了地图元素的缩放比例。drawFrame函数是ND显示的核心绘制入口，根据当前模式分发到不同的绘制流程。

Canvas提供的getContext(2d)方法返回Canvas 2D渲染上下文，提供了丰富的绘图API，包括路径绘制（beginPath、moveTo、ineTo）、几何图形（arc、rect）、样式设置（strokeStyle、fillStyle、lineWidth）以及坐标变换（translate、rotate、scale）等。本系统充分利用这些API实现罗盘玫瑰、航路点、导航辅助信息等复杂图形的绘制。Canvas 2D的像素级渲染能力使其成为航空仪表模拟的理想选择，能够精确控制每一条线的位置与颜色，满足ND显示的高精度要求。

系统CSS样式对ND显示区域、EFIS控制面板和数据面板的整个布局进行了规定。ND显示区域使用深色背景来模拟真实A320 ND的显示底色，EFIS控制面板使用浅灰色背景来模拟真实驾驶舱面板的金属质感。布局通过使用Flexbox来进行自适应排列，以此来保证在不同屏幕分辨率下能够达到显示效果。CSS样式设计遵循下面这些原则：ND显示区域使用宽高比为1:1的Canvas元素，通过CSS的max-width和height:auto来进行响应式缩放，让ND显示区域在不同屏幕尺寸下一直保持正方形比例。其次，EFIS控制面板通过网格布局来对各个功能区的位置进行组织，其中包括模式选择旋钮和范围选择旋钮。数据表明按钮和VOR调谐区按照真实A320 EFIS面板的物理布局进行排列，各控件之间保持着合适的间距和对齐。最后，数据面板，该面板显示飞机状态信息和导航数据等，采用Flexbox进行纵向排列，信息行通过等宽字体来模拟真实ND的数据显示风格，关键数据使用和真实ND一致的颜色编码，比如洋红色表示主动航路，绿色表示当前数据，蓝色表示表示距离单位。

网页动态内容的实现

ND模拟器所生成的动态内容是指那些随时间推移或者用户进行交互而发生实时变化的数据和画面。与静态内容（如HTML页面结构、C SS样式、Canvas画布初始化）不同，动态内容需要持续更新以反映飞机运动状态、导航数据变化、用户操作 响应。本系统实现动态内容主要依靠三个核心技术方式：React状态管理负责维护和更新应用状态，动画循环负责进行每帧的状态更新，Canvas绘制循环负责把最新状态渲染到画布上。这三种方法互相配合，组成了完整的动态内容展示。

React状态管理

系统的动态内容依靠React的状态管理方式来驱动。顶层状态在App.js文件中进行定义，包括ND模式、显示量程、飞机状态和系统状态。

其中，mode状态控制ND的显示模式，可选值为ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN五种，通过EFIS控制面板的模式选择旋钮切换。range状态控制显示量程，可选值为10、20、40、80、160、320NM六档，决定地图的缩放比例与罗盘上距离环的标注。aircraft状态封装了飞机的全部运动参数与导航参数，包括位置坐标（x,y）、航向（heading）、航迹（track）、地速（GS）、真空速（TAS）、风速风向（windDir,windSpeed）、高度（altitude）以及下一航路点ID（nextWaypointId），这些参数在动画循环中每帧更新。systemState状态管理辅助功能的显示开关，包括计时器（showChrono）、天气雷达（showWeather）、地形显示（showTerrain）。示例代码如图 4.2‑1所示。

动画循环与帧更新

ND显示器的动态更新依靠requestAnimationFrame驱动的动画循环来完成。requestAnimationFrame属于浏览器提供的专门用于动画的API。和setInterval或者setTimeout相比，它拥有下面这些优点：它可以自动和显示器的刷新率保持同步，一般维持在60Hz。页面不可见时会自动暂停来节省资源，也可以进行更精确的时间控制。在animate函数里，程序对每帧飞机位置、航向和导航数据进行更新，并利用setAircraft来触发NDDisplay组件进行重新渲染。

动画循环的启动时机在React的useEffect` 中控制，组件挂载时启动动画，组件卸载时通过cancelAnimationFr ame停止动画，避免内存泄漏。动画循环的帧率会受到浏览器刷新率的限制，一般为60 FPS，但是当遇到复杂场景时，因为Canvas渲染会产生计算开销，所以实际帧率会下降。系统在NDDisplay组件内部通过useEffect的依赖数组来对绘制频率进行控制，只有当mode、range、aircraft等重要状态发生改变时才会重新对Canvas进行绘制，这样就可以避免不必要的重绘操作。示例代码如图 4.2‑2所示。

具体的绘制流程如下：首先调用ctx.clearRect(0,0,width,height)清空整个画布，为新一轮绘制做准备。然后根据当前模式调用对应的绘制函数：ROSE模式下调用drawCompassRose绘制完整的360°罗盘，ARC模式下调用drawArcCompass绘制扇形罗盘，PLAN模式下调用drawPlanCompass绘制北向上的简化罗盘。接着绘制地图元素，包括飞行计划航路（通过drawRouteWaypoints函数）、航路点标记、VOR/NDB导航台等。之后绘制导航辅助信息，如距离环（drawRangeRing）、方位指针（drawBearingPointer）等。再绘制数据块，包括地速/真空速（drawGS_TAS）、风向风速（drawWindData）、航路点信息（drawWaypointInfo）等。

分层绘制模式使各功能模块的绘制逻辑保持独立，这有利于进行维护和扩展。每一层的绘制函数只负责该层的渲染工作，并利用Canvas的绘制状态来对各层之间的样式影响进行隔离，从而避免了全局样式被污染。

具体模式功能的实现

五种ND显示模式包括ROSE NAV、ROSE ILS、ROSE VOR、ARC和PLAN，这些模式组成了该模拟器的主要功能部分。各模式分别代表不同的飞行阶段和导航要求，并且具有各自特有的显示布局和绘制方式。本节从Canvas 2D渲染的角度，说明每种模式的实现原理和具体技术细节。五种模式的实现都依赖于统一的绘制模式，首先利用worldToScreen投影函数把世界坐标转成屏幕坐标，接着调用drawingUtils.js里的专门绘图函数来进行各个模式特有的图形元素绘制，最后叠加通用显示元素，包括飞机符号、航向指示和数据块等。各模式之间的切换是通过EFIS控制面板上的模式选择旋钮来触发的，NDDisplay组件会依据当前模式值动态地选择对应的绘制流程。

ROSE NAV模式

ROSE NAV模式是ND最基本的显示模式，飞机位于显示器中心，航向朝上，显示完整的360°罗盘玫瑰。该模式适用于航路巡航阶段，飞行员可以通过罗盘玫瑰直观地了解飞机当前航向与周围导航设施、航路点的相对位置关系。

罗盘Compass Rose包括同心圆环、角度刻度标记和方位标签。代码实现位置在utils/drawingUtils.js文件里的dr awCompassRose函数中。该函数根据当前航向来计算刻度线的旋转角度，并且绘制外侧刻度线和数字方位标签0、3、6、9、从30度开始每隔45度的白色实心三角形标记。罗盘绘制过程包括三个步骤：先画出外圈圆环和内圈圆环，外圈圆环用粗实线表示，内圈圆环用细实线表示，两个圆环之间的环形区域用来放置刻度标记。在圆环的外部画出角度刻度线，每间隔10°画出一条短刻度线，每间隔30°画出一条长刻度线，长刻度线的末端标记对应的角度数字，数字用白色填充，字体大小为14像素。最后从30°开始，每隔45°在外圈圆环外侧绘制一个白色实心小三角形，三角形的一个顶点指向罗盘中心，这样会增强方位辨识度。

地图投影采用等距方位投影（Azimuthal Equidistant Projection），以飞机位置为投影中心。该投影方式的特点是：从投影中心到任意点的距离与真实距离成比例，方向角保持正确，因此非常适合用于导航显示。在本系统中，世界坐标系采用笛卡尔坐标（单位为海里），屏幕坐标系以Canvas左上角为原点（单位为像素），通过投影函数将世界坐标映射到屏幕坐标，示例代码如图 4.3‑1所示。



图 4.3‑1 屏幕坐标计算

飞行计划航路用洋红色标示主动航路，用青色标示备用航路。航路点之间连接的线条包括直线航段和弧形过渡航段。航路绘制函数drawRouteWaypoints遍历航路点列表，对每个相邻航路点对执行以下操作：首先利用worldToScre en函数把两个航路点的世界坐标转换成屏幕坐标，然后按照航段类型，即直线或弧形，选择不一样的绘制路径。直线航段利用ctx.moveTo和ctx.lineTo进行绘制。弧形过渡航段利用ctx.arc绘制平滑曲线，用来模拟飞机在转弯时的航迹过渡。航路点标记用实心圆点来表示，主动航路的航路点标记显示为洋红色，备用航路的航路点标记显示为青色，当前目标航路点通过菱形标记来进行突出显示。

航向道LOC偏差指示利用罗盘上的航道杆和偏离杆来完成。洋红色航道杆指向ILS航道方向，偏。离杆相对于航道杆进行水平移动，该指标表示飞机相对中心线的横向偏差，每个刻度对应约0.8°，满偏量程在左右2个刻度范围内。下滑道偏差指示位于屏幕右侧的垂直刻度尺上，该刻度尺包括中间的黄色横线基准线、上下两个刻度。洋红色菱形指示器沿着垂直方向进行移动来表示飞机下滑道偏差，每个刻度代表大约0.4°。

ROSE VOR模式

ROSE VOR模式在ROSE NAV显示界面之上增加了VOR导航引导的相关信息，具体包括航道偏差指示器、VOR航道指针、VOR方位指针和TO/FROM状态标识。

航道偏差指示器包括航道杆Course Pointer、偏离杆Deviation Bar和TO/FROM标志，航道杆用洋红色指示选定航道方向，偏离杆按照VOR径向偏差计算结果进行横向移动，TO/FROM标志则依据飞机相对于VOR台的位置进行自动切换。CDI的绘制逻辑由drawCourseDagger函数来完成，该函数接收航道角度、偏差值、TO/FROM模式等参数，在罗盘中心位置绘制十字杆并且显示偏离指示。航道杆的旋转角度是航道和当前航向差值所决定的，偏离杆的横向偏移量是把偏差值乘以最大偏移像素数进行计算得到。TO/FROM标志用箭头符号表示，箭头指向中心表示TO即飞向VOR台，箭头背离中心表示FROM即飞离VOR台。

VOR方位指针用于指示VOR台相对于飞机的方位。VOR1方位指针使用实线绘制，从罗盘内圈到外圈之间绘制一条直线段，线段两端各有一个空心三角形，三角形指向VOR台方向。VOR1方位指针的绘制在drawBearingPointer函数中实现，该函数接收罗盘中心坐标、当前航向、VOR方位角、罗盘半径与内圈半径等参数。方位指针的绘制过程为：首先根据VOR方位角与当前航向计算指针在罗盘上的旋转角度，然后从内圈半径位置到外圈半径位置绘制直线段，最后在线段两端绘制空心三角形指示方向。

ARC模式

弧形模式是A320 ND特有的显示方式，飞机位于显示器底部中心，显示前方大约100度的扇形区域。该模式的主要特点是弧形视口进行坐标变换，把世界坐标投影到扇形显示区域里，并且使用同心圆弧来代替ROSE模式的距离环。离环用来表示距离范围。

ARC模式的视口计算包括三个步骤：第一步先确定扇形视口的几何参数，包括扇形圆心，它位于显示器底部中心下方位置。扇形半径和ROSE模式罗盘半径、扇形角度范围左右各约50°，共100°。本文先把世界坐标经过等距方位投影转换成以飞机位置为原点的极坐标，再依据极坐标的角度和半径来判断目标点是不是位于扇形区域内。角度处于正负50度范围内并且半径小于扇形半径的点可以保留显示，其余点会被裁剪。本文将保留的点从极坐标映射到屏幕坐标，同时把角度映射到扇形视口的水平位置，并且把半径映射到扇形视口的垂直位置。该坐标变换把圆形视口平滑地变成了扇形视口，飞行员能够集中观看飞机前进方向的空域信息。

ARC模式的距离指示使用同心圆弧来代替ROSE模式的同心圆环，圆弧的半径和距离保持着正比关系，弧长对应着扇形视口的宽度。距离标签被标注在圆弧的左侧或者右侧端点位置，并且用青色文字进行显示。

PLAN模式

PLAN模式（计划模式）以正北方向为上方，显示完整的飞行计划航路，飞机位置固定于显示器中心。该模式不进行航向旋转，所有元素均以地理北方向为基准显示，适用于航路规划与审查。该模式的核心特点是地图中心定位在目标航路点（飞机当前飞往的下一个航路点）上，而非飞机自身位置，且地图不进行航向旋转，所有元素均以地理北方向为基准显示。

PLAN模式和ROSE NAV模式的区别主要表现在以下方面。第一，地图中心定位有差别。ROSE NAV模式把飞机位置当作地图中心，而PLAN模式把目标航路点当作地图中心，这使飞行员可以全局角度来观察飞行计划的整体布局。其次，航向旋转处理方式有所不同：ROSE NAV模式通过使用当前航向对地图坐标进行旋转，来实现航向朝上的显示效果。PLAN模式里 mapRotation被设定为0，所有元素都按照地理北方向当作上方来进行显示。第三，飞机符号绘制方式不同：在PLAN模式中，飞机符号不固定在屏幕中心，而是绘制在地图坐标系中的实际位置，并通过ctx.rotate(toRad(aircraft.heading))旋转以匹配飞机的当前航向，使飞机符号在地图上移动和旋转。

PLAN模式的距离圈通过drawRangeRing(range/2)绘制单个虚线圆环，距离标签显示在圆环内侧。飞行计划航路的绘制逻辑与ROSE NAV模式相同，航路点与航段的显示范围取决于当前量程设置。PLAN模式同样显示下一航路点信息包括航向、距离、到达时间、识别码等数据。

EFIS控制面板

EFIS控制面板是用户与ND模拟器交互的主要界面，模拟了真实A320 EFIS控制面板的布局与功能。

交互旋钮元件

本系统交互功能的实现主要使用两种旋钮：离散值选择旋钮和连续值调节旋钮。离散值选择旋钮用于模式选择与范围选择。连续值调节旋钮用于VOR频率与CRS航道调节，支持精细调节与快速调节。

控制面板布局

EFIS控制面板参照真实A320的EFIS控制面板进行布局，该控制面板包括模式选择区、范围选择区、数据显示控制区和VOR调谐区。用户利用离散值旋钮对五种ND模式进行切换，利用离散值旋钮对10到320nm的六档量程进行调节。数据表明控制区利用按钮来切换天气雷达和地形等功能的显示状态。VOR调谐区具有自动和手动调谐的切换功能，也包括对频率和航道进行调节的功能。

EFIS控制面板采用组件化设计并遵循React的组件化开发原则，把面板拆分成多个独立的子组件：AirButton组件实现带状态指示的按钮，该按钮支持按下和弹起两种状态并且底部标签显示。ScrewHead组件模拟真实面板上的螺丝头装饰，提高面板的视觉真实感。ToggleSwitch组件实现左右拨动开关，主要进行模式切换。这些子组件使用组合和嵌套的方法，形成了完整的EFIS控制面板用户界面。

控制面板和ND显示组件之间进行的数据通信是利用React的Props传递来完成的。EFIS面板里的模式选择、范围调节、VOR调谐等操作利用回调函数onModeChange、onRangeChange、onVorTuningChange把这些用户操作传递到顶层App组件。件在更新状态后，通过Props把新状态传递给NDDisplay组件，触发Canvas进行重新绘制。该单向数据流设计保证了状态变更可以追踪，并且让各个组件之间保持低耦合。

航路编辑与显示

航路编辑功能由components/RouteEditor.js和components/RouteList.js组件实现，支持对航路点进行增加、删除、修改和查询等操作。RouteList组件把列表形式展示全部已建立的航路，每条航路显示名称、航路点数量和激活状态。用户点击航路项能够展开详情，利用按钮可以切换启动或备用状态或者删除航路。RouteEditor组件拥有航路点的详细编辑界面，界面包括航路点名称、经纬度坐标、航路点类型，包括航路点、VOR、NDB、机场等、航段类型，包括直线或弧形过渡等属性的编辑功能。WaypointEditor组件主要用来对单个航路点的属性进行编辑，并且可以支持用户在地图上通过点击来选择航路点，或者通过手动输入坐标的方式进行操作。

航路在ND上的显示由components/NDDisplay.js中的drawRouteWaypoints函数完成，主动航路以洋红色进行绘制，备用航路以青色进行绘制，航路点之间的连线包括直线航段和弧形过渡航段。航路显示的逻辑流程如下：首先从Fligh tPlanContext中获取当前启动航路和备用航路的航路点列表，然后遍历航路点列表，对每个相邻航路点对调用worldToScreen函数把世界坐标转换为屏幕坐标，最后根据航段类型选择直线或弧形绘制路径。航路点标记用实心圆点表示，当前目标航路点也就是飞机将要到达的下一个航路点，使用菱形标记进行突出显示，并且标注航路点名称和预计到达时间。

总结与展望

A320导航显示器ND属于现代民航客机座舱里的主要仪表设备，该显示器的显示逻辑比较复杂，符号模式非常严谨，会对飞行安全产生直接的影响。本文利用Web前端技术形成一套具有完整功能且可以进行交互的ND模拟系统，用来辅助航空电子设备的教学和训练，这提供了一种成本较低并且易于获取的技术方案。系统使用HTML、CSS和JavaScript进行建立，通过React框架对组件状态和数据流进行管理，依靠Canvas 2D API实现高性能的图形渲染，在浏览器中还原了A320 ND的主要显示功能和操作逻辑[19]。

在功能实现上，系统完整地实现了ROSE NAV、ROSE ILS、ROSE VOR、ARC、PLAN这五种ND显示模式，各模式都按照真实A320 ND的显示逻辑和符号标准进行，包括罗盘绘制、地图投影和坐标变换、ILS航向道和下滑道偏差指示、VOR航道偏差指示器CDI与TO/FROM判断、弧形视口计算等重要技术。EFIS控制面板形成了和真实A320外观一样的交互界面，里面包括模式选择、量程调节、航道设定等主要控制功能。飞行计划和航路管理系统利用React Context来完成航路的建立、修改、取消、启动或备用切换的功能，该系统支持直线航段和弧形过渡航段这两种连接方式。VOR/ILS导航显示拥有自动和手动调谐功能，可以显示航道偏离指示，并且提供仪表着陆引导服务。

该设计达到了以下目标：学生通过使用交互式网页界面，可以直观地理解导航显示器的工作原理，并且提高学习兴趣和效率。学生能够随时通过浏览器来访问仿真系统，不需要安装任何额外的软件，使使用门槛得到降低。教师利用教室的多媒体设备直接进行课堂演示，以增加教学过程的互动性。飞行员和民航专业学生可以利用仿真系统来进行导航仪表的操作练习，从而为后续的实际操作打下基础。系统运用组件化架构来进行模块化设计，各个功能模块之间具有低耦合和高内聚的特点，给后续的功能扩展和维护提供了良好基础。

虽然该系统已经完成了A320 ND的主要功能，不过和真实ND系统进行比较仍然存在一些差距。后续工作将主要围绕以下方面展开：第一是引入更多飞行数据和飞行参数，让导航显示器所显示的内容变得更加完整，这包括了实现ADF指示器、风数据显示、垂直导航指示等一些缺失的功能。二是把该设计同其他系统结合起来，比如A320的多功能控制显示单元MCDU，用来进行飞行管理系统的数据输入和显示，让用户可以输入和修改飞行计划、增减航路点、计算飞行距离及预计到达时间，从而得到比较完整的飞机操作体验。第三是考虑到移动设备的普及，本文探索把仿真系统扩展到移动平台的可行性，通过进行响应式设计和触控交互优化，使系统可以在平板电脑和智能手机上正常运行，并且探索跨设备连接功能。第四是完善和外部飞行模拟器的数据接口，以实现真实飞行数据的输入，进而提高模拟的真实性。

该系统在教学和训练上拥有很好的应用前景。教师在课堂教学中可以使用该系统直观地展示ND各模式的工作原理和显示逻辑，并且可以把抽象的理论知识转化为可视化的交互操作。在自主学习环境下，学生不需要依靠昂贵的训练设备，只通过浏览器就可以随时进行操作练习，从而加深对导航系统工作流程的理解。在实践训练中，该系统可以当作仪表操作的入门训练工具，让飞行专业学生预先熟悉ND界面的布局和功能，为后续的模拟机训练打下基础。该系统把理论同实践进行结合，可以在民航相关专业教学里发挥辅助作用。

附录D：软件使用说明

D.1 环境要求与启动

本模拟器为基于网页的应用程序，无需安装任何额外软件，只需满足以下环境要求：
（1）操作系统：Windows / macOS / Linux均可。
（2）浏览器：推荐使用Chrome 90+、Edge 90+、Firefox 90+或Safari 14+。
（3）网络：首次加载需连接互联网（用于加载React等依赖库），后续使用可离线运行。

启动方式一（推荐——直接访问网页）：
在浏览器地址栏中输入部署后的网页链接，即可直接打开模拟器界面。

启动方式二（本地开发运行）：
步骤1：确保已安装Node.js 18+和npm。
步骤2：打开终端，进入项目根目录，执行命令：npm install
步骤3：安装完成后，执行命令：npm run dev
步骤4：在浏览器中访问终端输出的本地地址（通常为 http://localhost:5173）。

D.2 界面布局

模拟器界面由以下三个主要区域组成：
（1）ND显示区域：位于界面中央，为600×600像素的深色方形区域，用于显示导航罗盘、飞行计划航路、导航台信息等。
（2）EFIS控制面板：位于ND显示区域下方，为浅灰色面板，包含模式选择旋钮、范围选择旋钮、VOR调谐控制区等功能控件。
（3）航路管理面板：位于界面右侧，包含航路列表、航路编辑器和地图加载功能。

D.3 基本操作步骤

步骤1：选择ND显示模式
在EFIS控制面板左侧，找到模式选择旋钮（MODE SEL）。点击旋钮的左右箭头，可在五种模式间切换：
· NAV（ROSE NAV）：全罗盘导航模式，飞机居中，显示360°导航信息。
· LS（ROSE ILS）：仪表着陆模式，显示ILS航向道和下滑道偏差。
· VOR（ROSE VOR）：VOR导航模式，显示VOR方位指针和航道偏离杆。
· ARC（ARC模式）：扇形显示模式，显示前方90°空域。
· PLAN（计划模式）：正北朝上，显示完整飞行计划航路。

步骤2：调节显示范围
在模式选择旋钮右侧，找到范围选择旋钮（RANGE SEL）。点击旋钮的左右箭头，可在10、20、40、80、160、320NM六档量程间切换。量程值越大，ND显示区域覆盖的地理范围越广。

步骤3：查看导航信息
切换至所需模式后，ND显示区域将自动显示对应的导航信息：
· 左上角显示地速（GS）和真空速（TAS）。
· 左上角第二行显示风向风速（格式：风向角度/风速）。
· 右上角显示下一航路点名称、航迹、距离和预计到达时间。
· 左下角和右下角分别显示VOR1和VOR2接收机的导航台信息。

步骤4：管理飞行计划
点击界面右侧的"航路管理"按钮，打开航路管理面板：
· 查看航路列表：显示所有已创建的航路。
· 编辑航路点：点击航路点可修改名称、经纬度坐标、类型等属性。
· 添加/删除航路点：在航路编辑器中执行增删操作。
· 切换启动/备用航路：在航路列表中选择航路并设置为启动或备用状态。

步骤5：加载自定义地图
在航路管理面板中，点击"加载地图"按钮：
· 从URL加载：输入JSON格式地图数据的网络地址。
· 从文件加载：选择本地的JSON格式地图文件。
加载成功后，地图中的航路点、导航台和航路信息将自动显示在ND上。

步骤6：VOR调谐操作
在EFIS控制面板右侧的VOR调谐区：
· 切换调谐模式：点击"AUTO/MAN"按钮，在自动调谐和手动调谐之间切换。
· 自动模式：系统自动选择飞行计划航路中最近的VOR台。
· 手动模式：通过频率调节旋钮输入指定VOR频率，选择对应的VOR台。
· 调节CRS航道：通过CRS旋钮设定VOR航道角度。

步骤7：辅助功能
EFIS控制面板上的辅助功能按钮：
· TERR（地形显示）：切换地形数据的显示。
· WXR（气象雷达）：切换气象雷达回波的显示。
· FAIL（故障模拟）：模拟ND系统故障时的显示效果。
